linWinPwn quick-use sheet

Run several AD collectors from Kali, keep their output together, then validate the useful leads.

Use this wrapper when you need coordinated directory, relationship and share enumeration. For one specific question, use the focused tool in the owning AD procedure. A collector result suggests a path; it does not prove permissions, host access or exploitation.

“Enumeration only” needs qualification. Upstream describes --auto this way, but the script also runs user=password checks, pre-created-computer authentication checks, Timeroast, AS-REP/Kerberoasting, offline cracking and vulnerability probes. Its anonymous branch can invoke the CVE-2022-33679 exploit. Treat it as a broad active assessment. Choose individual menu actions for narrower collection.

1. Choose a mode

NeedChooseBoundary
Inventory with deliberate tool selectionDefault interactive modeChoose a specific submenu action. Startup still contacts the DC and scans selected ports.
Broad assessment of an authorized lab domain--autoIncludes authentication checks and attack routines; automated target default is all domain servers.
Preview generated commands--no-execNot a network isolation boundary: startup has direct NetExec and Nmap calls outside the command wrapper. --offline additionally skips startup connectivity checks and implies no-exec, but is not a sandbox.

These are reference commands for later scoped practice. Exam permission depends on current OffSec rules and the actual features invoked; this page does not establish approval for the wrapper or its dependencies.

2. Prepare Kali

The upstream installer installs or upgrades many tools, uses sudo, writes under /opt/lwp-scripts and creates launchers in /usr/local/sbin. Review it before running. These setup commands belong on Kali, separate from the Windows notes workstation.

mkdir -p ~/oscp/tools/repos
git clone https://github.com/lefayjey/linWinPwn.git ~/oscp/tools/repos/linWinPwn
cd ~/oscp/tools/repos/linWinPwn
less install.sh
chmod +x install.sh
./install.sh
linWinPwn -h

Local check: help should list --auto, --targets and the supported credential flags. A successful help screen does not verify every dependency. In the menus, [X] (Missing) means the associated tool is unavailable.

All commands below assume the installed linWinPwn launcher. Replace DC_IP with the DC's IP address, DOMAIN with the AD DNS domain, USER with the account name, and PASSWORD/HASH with the matching secret. Use one credential method per invocation.

mkdir -p ~/oscp/work/TARGET/evidence/linwinpwn

3. Selective enumeration

Baseline: a valid domain account, working DC name resolution, and access to the relevant LDAP/SMB/Kerberos services. Interactive targets default to DCs; the explicit option makes the intended host set visible.

linWinPwn -t DC_IP -d DOMAIN -u 'USER' -p 'PASSWORD' --targets DC -o ~/oscp/work/TARGET/evidence/linwinpwn

From the main menu, select 2 → AD Enumeration, then choose one action at a time:

QuestionAD submenu selectionRead / next check
What users, groups and computers exist?3 — ldapdomaindumpReadable HTML/JSON inventory. Confirm interesting identities and memberships in the original directory data.
What relationships exist, using DC-focused collection?2ce — BloodHound CE DCOnlyUse a compatible CE importer. Check each useful edge's identity, object and required permissions.
What sessions or host relationships are visible?1ce — BloodHound CE all methodsBroader, noisier host contact. Host connectivity and collection rights limit results; absence is inconclusive.
What is the password policy?6 — NetExec policy enumerationRead lockout settings before considering any guessing. Policy collection itself does not authorize spraying.
Where are delegation or writable-object leads?9 — delegation; 11 — bloodyAD writable rightsCheck effective rights, object type, inheritance and identity before selecting an attack.
What SMB/RPC information can this identity read?4 — enum4linux-ngSeparate successful LDAP/RPC queries from denied or unsupported operations.

Menu labels are authoritative if numbering changes. For share permissions, return to the main menu and choose 8 → 1 (smbmap) or 8 → 2 (NetExec shares). For directory-based ADCS discovery, use 3 → 1 (NetExec); the ADCS submenu also contains credential dumping and certificate-forging actions, so do not run everything based on its title.

Anonymous interactive inventory — no credentials yet 
linWinPwn -t DC_IP --targets DC -o ~/oscp/work/TARGET/evidence/linwinpwn-anonymous

Select specific anonymous SMB/RPC/LDAP checks. Anonymous LDAP denial is common; it does not establish that no users or shares exist. Obtain an authorized identity before retrying authenticated collection.

4. Automated mode

Authenticated baseline: use only when the full batch's behavior fits the target scope. Place --targets after --auto: the argument parser resets targets to All when it encounters --auto.

linWinPwn -t DC_IP -d DOMAIN -u 'USER' -p 'PASSWORD' --auto --targets DC -o ~/oscp/work/TARGET/evidence/linwinpwn-auto

The current script runs DNS, AD, ADCS, SCCM and GPO collection, then brute-force checks, Kerberos routines, network/share scans, vulnerability checks and MSSQL checks. Steps may be skipped or fail when tools, rights or protocols are unavailable. The final completion banner does not prove complete coverage.

Scope limit: --targets controls selected host-oriented scan routines. Directory queries still inspect domain data, and some collectors discover/contact hosts independently. --targets DC is not a universal DC-only network boundary. For strict single-host work, select and inspect the individual collector instead.

Anonymous automated assessment — broader than anonymous inventory 
linWinPwn -t DC_IP --auto --targets DC -o ~/oscp/work/TARGET/evidence/linwinpwn-auto-anonymous

This can perform username discovery, user=password checks, pre-created-computer checks, Timeroast, roasting/cracking and CVE-2022-33679 exploitation when prerequisites and dependencies permit. Do not choose it just because you have no credentials.

5. Credential variants

These start the selective interactive menu. Add --auto --targets DC only when deliberately choosing the batch above. Credential support differs among child tools; one working authentication method does not mean all collectors support it.

NTLM hash — account identity plus LM:NT material 
linWinPwn -t DC_IP -d DOMAIN -u 'USER' -H 'LM_HASH:NT_HASH' --targets DC -o ~/oscp/work/TARGET/evidence/linwinpwn-hash

Use the documented LM:NT form. If only an NT hash is known, upstream's parser also accepts a 32-character NT hash; HASH must belong to the supplied identity. NTLM restrictions or missing protocol support can still block a collector.

Kerberos credential cache — existing valid ticket 
linWinPwn -t DC_IP -d DOMAIN -u 'USER' -K /absolute/path/USER.ccache --targets DC -o ~/oscp/work/TARGET/evidence/linwinpwn-ticket

The cache principal must match the intended identity. Check ticket lifetime, domain, DNS and clock alignment. Use hostnames that match service principals; replacing everything with IP addresses can break Kerberos.

AES key — Kerberos authentication 
linWinPwn -t DC_IP -d DOMAIN -u 'USER' -A 'AES_KEY' --targets DC -o ~/oscp/work/TARGET/evidence/linwinpwn-aes

Requires the correct account's AES key and Kerberos connectivity. A key mismatch, unsupported encryption type or clock skew prevents authentication.

PFX certificate — certificate-backed identity 
linWinPwn -t DC_IP -d DOMAIN -u 'USER' -C /absolute/path/USER.pfx --cert-pass 'PFX_PASSWORD' --targets DC -o ~/oscp/work/TARGET/evidence/linwinpwn-certificate

The PFX must include its private key and map to the intended identity. Omit --cert-pass for an unencrypted PFX. Certificate mapping, PKINIT support and child-tool support can constrain usable checks.

The wrapper constructs shell command strings. Shell-sensitive secrets can require extra care; inspect the generated command rather than repeatedly retrying a failed login. Arguments, preview output and collected files can expose secrets even where the command log masks them. Keep output private.

6. Scope & transport

Explicit host list for the host-oriented automated checks

Create /absolute/path/servers.txt with one approved IP or hostname per line. Domain collectors retain their own coverage as described above.

linWinPwn -t DC_IP -d DOMAIN -u 'USER' -p 'PASSWORD' --auto --targets File=/absolute/path/servers.txt -o ~/oscp/work/TARGET/evidence/linwinpwn-list
One selected member server for host-oriented checks

-t remains the DC. --targets IP=TARGET selects a separate approved host for the routines honoring this option.

linWinPwn -t DC_IP -d DOMAIN -u 'USER' -p 'PASSWORD' --auto --targets IP=TARGET -o ~/oscp/work/TARGET/evidence/linwinpwn-host
LDAPS with channel binding 
linWinPwn -t DC_IP -d DOMAIN -u 'USER' -p 'PASSWORD' --ldaps --ldap-bind --targets DC -o ~/oscp/work/TARGET/evidence/linwinpwn-ldaps

Requires reachable TCP/636 and compatible client dependencies. Signing/channel-binding support is not uniform across tools; inspect the failed collector's options/version.

LDAP signing on ordinary LDAP 
linWinPwn -t DC_IP -d DOMAIN -u 'USER' -p 'PASSWORD' --ldap-sign --targets DC -o ~/oscp/work/TARGET/evidence/linwinpwn-signed
Force Kerberos where supported — password credential 
linWinPwn -t DC_IP -d DOMAIN -u 'USER' -p 'PASSWORD' --force-kerb --targets DC -o ~/oscp/work/TARGET/evidence/linwinpwn-kerberos

Requires correct name resolution, SPNs, time and Kerberos reachability. Upstream supports this switch with a password or NTLM hash; it is not a guarantee that every child tool uses Kerberos.

VPN interface and DNS over TCP 
linWinPwn -t DC_IP -d DOMAIN -u 'USER' -p 'PASSWORD' -I tun0 --dns-ip DC_IP --dns-tcp --targets DC -o ~/oscp/work/TARGET/evidence/linwinpwn-vpn

Selecting an interface controls the wrapper's attacker-interface values; it does not create routes or force all child-tool traffic through a tunnel. TCP DNS is useful for transports that cannot carry UDP, but every required protocol still needs a working route.

Configuration changes: --auto-config changes time synchronization and edits /etc/hosts, /etc/resolv.conf and /etc/krb5.conf. It is deliberately omitted from the baseline. Fix the necessary DNS/time setting explicitly, or review this behavior before opting in.

7. Read the results

The wrapper appends linWinPwn_DOMAIN/ beneath the chosen -o directory. Separate output roots for different runs/identities avoid mixing stale evidence. Inspect raw tool files and the command log before trusting a wrapper summary.

Location / clueWhat it establishesNext
DomainRecon/, Users/, Servers/Collected objects, names, relationships and hosts under this identity's visibilityValidate the exact object/permission in AD manual enumeration.
BloodHound CE JSON in DomainRecon/Collector-derived graph dataImport into a compatible CE instance, inspect a candidate path and check edge prerequisites in AD automatic enumeration.
Shares/ says READReported share access, not proof of useful file contents or write/execute rightsConfirm a specific share/file with SMB enumeration.
Kerberos/ contains $krb5asrep$ / $krb5tgs$Crackable response/ticket material, not a recovered passwordCheck format and recovery options in hash cracking; validate any recovered credential separately.
Vulnerabilities/ or ADCS/ flags a candidateTool-specific hypothesisVerify service/version, template or ACL conditions manually before selecting an exploit.
Missing tool, denied access, timeout or empty outputIncomplete or failed collectionRepair that dependency, permission or connectivity check; do not conclude the path is absent.

Keep credential results, tickets, hashes, graph data and transcripts in private evidence. Re-enumerate after an identity/access change, and record which identity and command produced each useful observation.

8. Troubleshooting

SymptomCheck / action
“Target is not an IP address”-t requires the DC IP, not its hostname. Domain names belong in -d.
LDAP failure / cannot discover DC domainCheck the actual LDAP endpoint, routing and DNS. Use --ldaps when appropriate; --dc-domain DOMAIN supplies missing metadata, but does not repair connectivity.
Authentication failure or lockout messageStop automatic retries. Confirm identity/domain, credential validity, account state and lockout policy; inspect the exact child command.
SMB works but LDAP is deniedDifferent protocols enforce different policies. Check signing/channel binding and client support, then retry the specific LDAP collector.
Kerberos skew, SPN or ticket errorCheck time, FQDN resolution, realm, cache principal and expiry. --use-ip can help some NTLM/DNS cases but is not a general Kerberos fix.
[X] (Missing), missing script or import errorThe wrapper is not a self-contained dependency bundle. Inspect installation output and the expected path under /opt/lwp-scripts; repair the specific dependency.
Graph import failsMatch collector and BloodHound edition/schema. The CE menu entries and legacy entries are separate.
Batch “completed” but key results absentReview skipped steps, errors and saved files. Run only the missing collector with suitable rights/connectivity.

9. Tooling for this section

Baseline: linWinPwn on Kali with its dependencies; start with the selective password invocation. Requires routed access to the DC, the selected protocols, and a valid identity for authenticated collection. Useful output is the individual collector's saved evidence. A missing dependency or denied operation limits only that collection, not the existence of the underlying AD objects.

Focused alternatives: use BloodHound / LDAP inventory procedures for selected collection, built-in/manual directory checks for validation, and SMB procedures for a specific share. Their setup and direct invocations stay in those owning pages.
