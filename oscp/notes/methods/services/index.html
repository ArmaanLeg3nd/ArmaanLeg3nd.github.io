    1.2 Extract opportunities from services

    Strategy map | Master Notes | Operational index | Cheatsheets

    A service can disclose names, files, rights or execution. Test authentication, read, write and execution separately. A write becomes an execution path only when a useful consumer and trigger exist.

    Speedrun blocks: 2; authenticated re-enumeration throughout. Documented methods: 17.

    Examples are hypothetical study material. Apply commands only to an assigned scope during the later practice phase. A method is enabled by its prerequisites; its presence here does not establish a vulnerability or practical mastery.

    1.2.1 First pass: tools and findings

    Use the branch matching the current host, identity and observed result. Tool output supplies leads; the linked procedure verifies and uses the exact condition.

    1.2.1.1 Try SMB with the actual access context

    Use the anonymous form first when no credentials exist; use the authenticated variant when an identity is available.

    smbclient -N -L //TARGET
    • If A readable share contains config, backups or keys: Read the exact file and record its source before testing any recovered value. → Classify the artifact and its identity context.
    • If A working domain identity: Enumerate domain shares with that identity; share listing alone is not file access. → Read domain shares, SYSVOL and NETLOGON for useful artifacts.
    • Otherwise: SMB is denied: inspect another discovered protocol, not repeated guesses against the same identity. → Identify applications and validate selected NSE checks.

    1.2.1.2 Query exposed names and configuration

    Use only an observed/assigned community and the correct SNMP version; preserve the returned OIDs.

    snmpwalk -v2c -c COMMUNITY TARGET 1.3.6.1.2.1.1
    • If Process arguments or configuration contain an account value: Classify its account scope and format. → Classify the artifact and its identity context.
    • If A hostname or directory-service clue: Resolve it through the relevant name service. → Expand names through DNS records and zone transfers.
    • Otherwise: No useful SNMP response: return to the confirmed service list and choose its native client. → Identify applications and validate selected NSE checks.

    1.2.1.3 Inspect database identity and grants

    Use this branch only for confirmed SQL Server with an accepted login. Other database clients are separate procedures.

    SELECT SYSTEM_USER, ORIGINAL_LOGIN(), @@VERSION;
SELECT IS_SRVROLEMEMBER('sysadmin');
    • If A permitted impersonation or command facility: Check the effective login and the exact enabled operation before attempting an OS effect. → Use SQL Server rights, impersonation and command facilities.
    • If MySQL/MariaDB identified instead of SQL Server: Use the MySQL/MariaDB grants and file rules rather than SQL Server syntax. → Use MySQL/MariaDB data and file primitives.
    • Otherwise: Login succeeds but the action is denied: inspect grants under the same identity. → Use SQL Server rights, impersonation and command facilities.

    1.2.2 Discovery workflow

    Start with application evidence from discovery; anonymous access, valid credentials and useful rights are separate questions.

    Follow these observations into a method; the detailed recognition routes below show synthetic output and the checks still needed.

    1. Use the matching protocol client and establish which identity the service accepts: Use anonymous or authenticated FTP file access; Enumerate SMB/RPC shares, files and identities; Use SSH passwords, keys and forwarding-capable access.
    2. Treat file-service namespaces and exact-name retrieval as separate mechanisms: Inspect RPC/NFS exports and effective file identity; Inspect rsync modules and retrieve selected artifacts; Retrieve an evidence-backed file over TFTP.
    3. Investigate names, account clues and configuration with the available service context: Expand names through DNS records and zone transfers; Extract configuration and process information through SNMP; Enumerate SMTP identities and accessible mailbox protocols; Discover LDAP naming contexts and authenticated search.
    4. For databases inspect the current identity and grants before file or execution hypotheses: Use MySQL/MariaDB data and file primitives; Use SQL Server rights, impersonation and command facilities; Use PostgreSQL data and privileged program execution.
