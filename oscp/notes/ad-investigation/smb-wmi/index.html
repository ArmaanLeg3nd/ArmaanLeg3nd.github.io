    6.4.3 Execute using SMB or WMI mechanisms

    §6 — AD Notes | §6.0 — Quick Reference | §6.5.3 — Read output

    A scoped host, compatible authentication and verified remote execution rights. A visible writable share alone is insufficient.

    Where to look: For service-based execution inspect administrative share/file delivery and service-control rights. For WMI/DCOM inspect RPC endpoint/dynamic transport and namespace/COM authorization. Track execution separately from output retrieval.

    Expected behavior / secure boundary: Remote administrative execution is deliberately privileged. A local Administrators membership can be affected by remote token filtering/policy. An output-file failure can occur after execution; avoid blindly rerunning a state-changing command.

    These commands are study references for a later scoped exercise. Replace placeholders for the selected environment; the output below is synthetic, not a recorded target result. Commands that collect secrets, request tickets, create sessions or change directory state require their stated prerequisites.

    6.4.3.1 Execute on a selected host through verified administrative SMB access SMB execution using Impacket

    Run: Kali / Linux with Impacket. Requires: Required administrative share/service-control rights and compatible authentication. Effect: Remote execution; may upload files and create/remove a service.

    6.4.3.1.1 Authenticate with a known password in the correct account scope Password

    # Password
impacket-psexec 'DOMAIN/USER:PASSWORD@TARGET'

    6.4.3.1.2 Authenticate with the account's NT hash where supported NT hash / Pass-the-Hash

    # NT hash / Pass-the-Hash
impacket-psexec -hashes :NT_HASH 'DOMAIN/USER@TARGET'

    6.4.3.2 Execute on a selected host through verified administrative SMB access SMB execution using native Windows PsExec

    Run: Windows with Sysinternals PsExec. Requires: Required target administrative/service rights and selected credentials. Effect: Remote execution/service activity; first use can accept the tool EULA.

    PsExec64.exe -accepteula \\TARGET_HOST -u DOMAIN\USER -p PASSWORD cmd.exe

    What this checks: PsExec-style and SMBExec-style mechanisms differ in service, file and output handling. They require their respective access paths. WMI is a separate mechanism with RPC/dynamic-port requirements, documented in the linked full procedure.
