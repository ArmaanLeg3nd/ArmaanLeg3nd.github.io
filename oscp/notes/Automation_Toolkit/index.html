    0.8 Choose an enumeration toolkit

    Main index · Tools by task · Attack Strategy Map

    Build on established collectors: AutoRecon for network/service orchestration, PEASS for local hosts, and SharpHound/BloodHound Community Edition for AD relationships. Keep the existing procedures beside their output to interpret findings and validate prerequisites. A collector completing does not establish a complete attack surface or practical competence.

    Use the compact automation choices for the current working set and exact replacement boundaries. These are alternatives selected by missing information, not a checklist to run in full. AutoRecon replaces routine Mynmap/nmapAutomator orchestration; pspy adds live process observation; Seatbelt is retained for focused artifacts; PrivescCheck is an alternative/second opinion. Native helpers are fallbacks or focused gap checks, and the launchers add evidence handling rather than a second scanner engine. Keep manual validation, authenticated contexts and focused host/session collection even when an overlapping broad pass is retired.

    0.8.2 Preferred orchestration base: AutoRecon

    AutoRecon exposes plugin selection and preserves the underlying commands/results. Keep its orchestration/report structure and configure reviewed plugins rather than rewriting its scanner. The current repository is AutoRecon/AutoRecon; older Tib3rius links redirect there.

    Review automatic run methods separately from generated manual suggestions. In the inspected source, SMB brute-force and ODAT suggestions are manual commands. Conversely, the optional SMB vulnerability plugin actually runs smb-vuln-* with unsafe=1. Do not enable it wholesale. HTTP/MSSQL Nmap plugins use broad script expressions, and directory discovery can follow redirects; inspect concrete behavior and scope. A safe tag is an author label, not exam approval.

    Source checks: SMB vulnerability plugin, HTTP Nmap plugin, MSSQL Nmap plugin, manual SMB suggestions.

    Use the plugin controls to allowlist reviewed behavior and retain expanded commands. Keep full TCP discovery distinct from service detection and top-100 UDP coverage, which is partial. Review redirects/discovered names before more connections. The discovery and service procedures remain the validation baseline.

    Runnable profiles: The toolkit launchers now provide an explicit AutoRecon plugin profile and focused web/SMB/LDAP/host/AD entry points. They use existing tools, stage fingerprint-matching plugins and retain raw output; they do not install dependencies or automate an exploitation chain. The selected plugin set is pinned, while the installed framework, NSE library and other dependencies still need trusted matching versions. No all-default invocation or full upstream feature set is designated exam-approved.

    0.8.3 Host and AD collectors

    The linPEAS builder can select checks; release builds contain broad coverage. Retain the output and validate highlighted leads with the Linux escalation procedure. Use pspy when the missing evidence is a recurring privileged consumer, rather than repeatedly rerunning static checks.

    winPEAS distinguishes normal checks, optional domain collection and extra features. Its optional -vulnpackages sends package names/versions to an online lookup: exclude that from an offline exam-evidence workflow. Optional WSL/linPEAS download execution and external lookups need separate review. PrivescCheck provides readable reports and separate extended/audit/risky categories; an EDR/noise label is not itself an exam-permission category. Validate with the Windows escalation procedure.

    For AD, use the SharpHound version supported by the deployed Community Edition. Begin with appropriate directory collection, then use focused host/session collection only where scope and evidence justify it. The domain-mapping procedure owns these variants. enum4linux-ng supplies the SMB/RPC view; ldapdomaindump supplies a readable LDAP inventory. The latter's --minimal reduces retained attributes, while optional hostname resolution needs scope review. Its old BloodHound conversion targets obsolete 1.x formats, not a current CE graph.

    Our native helper stays a fallback and interpretation bridge. Expand upstream configuration and links before expanding it into another PEASS. Check the actual upstream licenses before redistributing a combined package; PEASS includes GPL-based terms and integration clarifications. Do not bulk-copy scanners into a new bundle.

    CandidateAssessment
    yaldobaoth/OSCP-ScriptsUseful convenience wrappers and workflow ideas, not a broad enumeration engine. Its AD wrapper also performs roasting; its psexec wrapper generates/executes a shell. The installer changes shell PATH and sudo secure_path. No LICENSE file was found in the inspected tree; review reuse permissions and each script before adopting the collection.
    nmapAutomatorA smaller Bash alternative for staged scans and recon suggestions. Its vulnerability modes use broad vuln/vulners selections; do not adopt All as an exam profile. Inspected source is older than current AutoRecon, which alone does not prove breakage.
    linWinPwnBroad AD wrapper with enumeration and explicit attack operations. It documents an enumeration-only automatic mode, but discovery can still span servers and active checks. Keep it as an optional, separately audited configuration rather than an unattended default.

    The example repository uses an ordinary windows/x64/shell_reverse_tcp payload, not Meterpreter. msfvenom alone does not imply the restricted Metasploit/Meterpreter target allowance was consumed; the complete wrapper still needs feature-specific review. Function names and OSCP branding do not establish permission.

    0.8.5 Policy and use boundaries

    After new credentials, repeat the relevant directory/group/host-access collection using the new identity. After a new route, use the same network/service collectors against explicit reachable scope through the verified transport; do not assume raw SYN/UDP behavior works through every SOCKS proxy. The lateral-movement and pivoting procedures own the access and route checks. No automatic collector chooses the exploitation path or replaces the evidence/reporting workflow.

    The exam guide and FAQ control restricted actions. Automated enumeration is distinct from automatic exploitation; wrappers inherit the restrictions of the features they actually run. No named OffSec approval or live-lab validation is claimed here.

    Use explicit scope, controlled local evidence, compatible versions and manually verified leads. During concept study, inspect saved/synthetic output and the owning procedures; target-based execution remains for the later practice phase.
