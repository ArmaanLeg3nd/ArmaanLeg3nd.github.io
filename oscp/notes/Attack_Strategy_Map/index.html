Choose an objective, compare the methods by their prerequisites, then open a self-contained entry. Each entry explains how to find its enabling conditions, why it works, how to execute and verify it, how failures change the decision, and which methods its result can unlock.

The map contains 166 documented methods across 15 topic guides, accounting for all 15 speedrun blocks and the eight grouped study units. Counts describe this preparation inventory, not every vulnerability or environment-specific chain that can exist.

Discover attack surfaces

Source and reachability

  • Validate the source path and discover hosts
  • Enumerate reachable endpoints from a Windows source

Transport coverage and application identity

  • Discover TCP ports with SYN or connect scans
  • Probe UDP and resolve ambiguous silence
  • Identify applications and validate selected NSE checks
  • Discriminate unknown listeners and use scanner alternatives

Evidence and re-enumeration

  • Validate uncertain results and rebuild the service queue

  • Enumerate SMB/RPC shares, files and identities
  • Inspect RPC/NFS exports and effective file identity
  • Use SSH passwords, keys and forwarding-capable access

Identity and configuration disclosure

  • Expand names through DNS records and zone transfers
  • Extract configuration and process information through SNMP
  • Enumerate SMTP identities and accessible mailbox protocols
  • Discover LDAP naming contexts and authenticated search

  • Inspect Redis access and persistence boundaries

Remote access and uncommon applications

  • Validate RDP, WinRM, VNC and Telnet access contexts
  • Investigate SIP/IRC identity and configuration clues

  • Convert database rights into a file or operating-system effect

Paper-based chain rehearsal

  • Linux standalone: Validate the source path and discover hosts → Discover TCP ports with SYN or connect scans → Establish scheme, host, redirects and request state → Map functions, roles and normal requests manually → Read files through directory traversal → Classify the artifact and its identity context → Validate known passwords and context-specific reuse → Use SSH passwords, keys and forwarding-capable access → Establish Linux state and choose an escalation candidate → Use an allowed sudo operation to cross a privilege boundary → Establish Linux state and choose an escalation candidate.

  • Windows standalone: Validate the source path and discover hosts → Discover TCP ports with SYN or connect scans → Establish scheme, host, redirects and request state → Map functions, roles and normal requests manually → Establish upload acceptance, storage and retrieval → Execute an uploaded file through a compatible handler → Verify command execution, host and represented identity → Establish Windows token, host and process context → Change a privileged service's executable configuration → Establish Windows token, host and process context.

  • AD roast and movement: Establish domain identity, DC, DNS, time and route → Enumerate directory objects with native, LDAP and PowerView approaches → Request a selected service ticket for offline service-account recovery → Recover passwords with feasible dictionary, rule and mask attacks → Validate known passwords and context-specific reuse → Match route, destination service and effective authorization → Use WinRM, WinRS or PowerShell remoting → Establish Windows token, host and process context → Select a privilege-backed impersonation or object-control route → Obtain accessible live logon-session credential material → Recover or reuse an NT password hash → Select password, NT hash, key-to-ticket or ticket authentication → Execute through uploaded service creation using PsExec.

  • AD replication and evidence: Establish domain identity, DC, DNS, time and route → Enumerate directory objects with native, LDAP and PowerView approaches → Validate effective directory-object control → Use validated directory replication rights for bounded credential proof → Capture state-transition, proof and exploit-adaptation evidence → Build and validate the report and submission artifacts.

  • Pivoted domain access: Discover pivot interfaces, routes and internal service context → Route a selected internal subnet through Ligolo-ng → Preserve DNS, Kerberos names and time across a pivot → Establish domain identity, DC, DNS, time and route → Enumerate directory objects with native, LDAP and PowerView approaches → Collect focused BloodHound data and validate an attack path → Validate effective directory-object control → Add a controlled identity to a group through effective membership rights → Use WinRM, WinRS or PowerShell remoting.

  • Execution and callback repair: Verify command execution, host and represented identity → Connect a Linux reverse shell through an available interpreter → Diagnose connection direction, listener and session failures in order → Pair staged payloads with the correct handler and session lifecycle → Verify command execution, host and represented identity.

At every arrow identify the produced capability and the next method's missing prerequisite. An expected result in these examples is hypothetical, not recorded lab evidence.

Study order and boundaries

Use Units 1–8 in the speedrun study sequence: Blocks 1+2; 3+4; 5; 6+7; 8 then 9; 13 fundamentals then 10→11→12; remaining 14; and 15. Relevant execution diagnostics recur throughout.

Core methods follow the established OSCP preparation route. AD CS, delegation/RBCD, broader GPO/ticket-forging branches and less-common service/tunnel options retain their explicit conditional context. Their prerequisites must be verified before selecting them.

Dedicated buffer-overflow and shellcode development remain excluded by learner choice; selecting, compiling and adapting an existing memory-corruption PoC remains covered. Commercial/mass vulnerability scanners, automatic exploitation and prohibited spoofing workflows are not operational exam paths. Some course topics therefore have recognition-only or conditional treatment. Read the current official exam guide before choosing restricted framework features; the Body of Knowledge describes competencies separately from tool permission.

Concept study includes the worked commands and reasoning here. Practical exploitation and independent retests follow the learner's explicit closure of the concept phase. Study coverage is separate from practical competence.
