Web Mapping Cheatsheet

← Cheatsheet index · Complete HTTP procedure · Next: web exploitation · Mechanics | Strategy map | Study methods: Map useful web behavior

Use when: an HTTP(S) endpoint must become an evidence-labelled application map. Replace placeholders and keep each identity's cookies/tokens separate.

First five minutes

curl -skL -D headers.txt -o body.html http://TARGET:PORT/
curl -sk -o /dev/null -w 'code=%{http_code} bytes=%{size_download} type=%{content_type} redirect=%{redirect_url}\n' http://TARGET:PORT/
curl -sk http://TARGET:PORT/robots.txt
curl -sk http://TARGET:PORT/sitemap.xml

Record:

scheme://host:port | redirect/title/certificate | anonymous/authenticated role
METHOD PATH | INPUT | OBJECT/FUNCTION | STATUS/LENGTH/MARKER | NEXT TEST

Burp manual loop

Scope target -> browse normally with Intercept off -> Proxy history
-> send interesting request to Repeater -> unchanged baseline
-> change one field/header/cookie/method/object -> compare -> save decisive pair

Replay curl through Burp:

curl -sk -x http://127.0.0.1:8080 -c cookies.txt -b cookies.txt http://TARGET:PORT/PATH

Useful artifacts

curl -sk http://TARGET:PORT/.git/HEAD
curl -sk http://TARGET:PORT/openapi.json
curl -sk http://TARGET:PORT/swagger.json

Inspect HTML comments, hidden inputs, forms, JavaScript route strings, fetch/XHR calls, source maps, cookies and response headers.

Content discovery

Calibrate with a random nonexistent path, then:

gobuster dir -u http://TARGET:PORT/ -w /usr/share/wordlists/dirb/common.txt -t 10 -o gobuster-root.txt
gobuster dir -u http://TARGET:PORT/ -w WORDLIST -x php,txt,bak,old,zip -t 10 -o gobuster-ext.txt

Authenticated:

gobuster dir -u http://TARGET:PORT/ -w WORDLIST -c 'SESSION=VALUE' -H 'Authorization: Bearer TOKEN' -t 10 -o gobuster-auth.txt

Confirmed soft-404 length:

gobuster dir -u http://TARGET:PORT/ -w WORDLIST --exclude-length NOISE_LENGTH -t 10 -o gobuster-filtered.txt

Check 200, redirects, 401, 403 and 405. A tool result is a candidate until manually reproduced.

Alternative engines, same decision:

feroxbuster -u http://TARGET:PORT/ -w WORDLIST -x php,txt,bak,old,zip -o ferox.txt
ffuf -w WORDLIST -u http://TARGET:PORT/FUZZ -ac -of json -o ffuf-content.json
wfuzz -c -z file,WORDLIST --hc 404 http://TARGET:PORT/FUZZ

-ac/status filters are starting points, not proof. Calibrate against random paths and compare stable body markers, lengths and redirects.

Virtual hosts

gobuster vhost -u http://DOMAIN:PORT/ --append-domain -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt -o vhosts.txt
ffuf -w WORDLIST -u http://TARGET:PORT/ -H 'Host: FUZZ.DOMAIN' -ac -o ffuf-vhosts.json
curl -sk -H 'Host: CANDIDATE.DOMAIN' http://TARGET:PORT/

Compare candidate and random Host responses before accepting a vhost.

Parameters and object values

ffuf -w /usr/share/seclists/Discovery/Web-Content/burp-parameter-names.txt -u 'http://TARGET:PORT/PATH?FUZZ=test' -ac -o params-get.json
ffuf -w WORDLIST -u http://TARGET:PORT/PATH -X POST -H 'Content-Type: application/x-www-form-urlencoded' -d 'known=value&FUZZ=test' -ac -o params-post.json
ffuf -w NUMBERS -u 'http://TARGET:PORT/api/objects/FUZZ' -H 'Authorization: Bearer TOKEN' -mc all -fc 404 -o object-values.json

APIs

curl -ski http://TARGET:PORT/api/v1/PATH
curl -ski -X OPTIONS http://TARGET:PORT/api/v1/PATH
curl -ski -X POST -H 'Content-Type: application/json' -d '{"username":"TEST_USER","password":"TEST_PASSWORD"}' http://TARGET:PORT/api/v1/login

PATH | METHOD | IDENTITY/ROLE | OBJECT/PROPERTY | RESULT | NEXT

405 often means valid route/wrong method. Validation errors disclose schema candidates. Verify every token through a separate authorized request.

Common failure decisions

SymptomNext action
All paths return 200Measure a random path; filter only confirmed noise
Browser works, curl failsCopy exact Host/cookie/token/CSRF/method/content type from Burp
Repeated login redirectsRefresh auth context; use a separate cookie jar
403Compare random path; retry only with legitimate new identity
405Inspect Allow, docs and JavaScript; test supported method
Candidate disappears after filteringRemove filter and manually compare body markers

ffuf with the captured request

Save a manually verified raw request as request.txt and place FUZZ at one input. Preserve the correct Host, cookie and body. Choose the actual transport:

ffuf -request request.txt -request-proto https -w WORDLIST -mc all -ac -t 10 -o request-https.json
ffuf -request request.txt -request-proto http -w WORDLIST -mc all -ac -t 10 -o request-http.json

Replay outliers. Uniform login redirects → refresh the session; changing CSRF tokens → fix token handling before further fuzzing. Full mapping procedure.

Discover and recognize candidates

Use these discovery checks to find a candidate, then validate the missing conditions. Cues are illustrative; complete synthetic outputs and three-outcome examples are in the linked study entries.

Map useful web behavior

Find: Establish scheme, host, redirects and request state

Request the assigned HTTP endpoint without following redirects blindly; inspect location, cookies and alternate scheme/hostname behavior.

curl -skD headers.txt -o body.html http://TARGET:PORT/
curl -skI https://TARGET:PORT/

Recognize: The hostname/scheme redirect identifies the application request context to reproduce.

Validate next: Confirm the hostname routes to the assigned address and preserve its TLS/Host/session state.

Establish scheme, host, redirects and request state.

Find: Map functions, roles and normal requests manually

Browse the site's normal account, export, upload and download features while recording requests in the browser/proxy.

curl -sk -b cookies.txt -D response-headers.txt http://TARGET:PORT/PATH

Recognize: The normal request exposes a file-selecting input discovered through functionality, not guessed from a payload list.

Validate next: Find the actual input semantics, account/role and normal response before file/read/authorization tests.

Map functions, roles and normal requests manually.

Find: Inspect source, backups, configuration and repository artifacts

Inspect linked JavaScript/source, robots/sitemaps, relevant backups and a bounded Git metadata check from the mapped web application.

curl -sk http://TARGET:PORT/robots.txt
curl -sk http://TARGET:PORT/.git/HEAD

Recognize: The path and Git reference are investigation leads; neither proves a working secret or complete repository.

Validate next: Compare missing-path controls, retrieve actual permitted artifacts and verify recovered history/account context.

Inspect source, backups, configuration and repository artifacts.

Find: Discover directories and files with controlled response filtering

Establish the application's missing-path response, then run a bounded content search with the existing session/host context.

curl -sk -D - http://TARGET:PORT/KNOWN_MISSING_PATH

Recognize: The candidate's actual function differs from the soft-404 control despite equal status codes.

Validate next: Request a known-missing path under the same host/session and compare status, body and length. Open each distinct Gobuster/ffuf result; a uniform login page or soft-404 is a filter problem, not a directory finding.

Discover directories and files with controlled response filtering.

Find: Discover virtual hosts and hostname-selected applications

Collect hostnames from redirects, certificates, DNS and source; compare named requests against an invalid-host control.

curl -sk --resolve HOSTNAME:PORT:TARGET https://HOSTNAME:PORT/

Recognize: A reproducible hostname-selected application is a new mapping target on the same address.

Validate next: Send a random Host header as a negative control, compare the candidate's real response, then browse it with the correct hostname. A different status caused only by redirects or a default site is not a confirmed vhost.

Discover virtual hosts and hostname-selected applications.

Find: Map parameters, API methods, objects and writable properties

Capture a valid API request, inspect its schema/client code and compare allowed methods and controlled object/role contexts.

curl -sk -i -b cookies.txt http://TARGET:PORT/api/PATH

Recognize: The actual object, method and writable input are known; returned owner/role fields are only candidate security boundaries.

Validate next: Determine field binding, ownership, persistence and server authorization with controlled accounts.

Map parameters, API methods, objects and writable properties.
