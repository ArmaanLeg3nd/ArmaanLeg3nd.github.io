Discovery and Scanning Cheatsheet

← Cheatsheet index · Complete procedures · Next: service opportunities · Mechanics | Strategy map | Study methods: Discover attack surfaces

Use when: an assigned IP/list must become a defensible queue of reachable applications. Replace every placeholder and stay inside explicit scope.

Fast baseline: one directly reachable host

mkdir -p scans
ip -br addr
ip route get TARGET
sudo nmap -sS -n -oA scans/tcp-initial TARGET
sudo nmap -sS -n -p- --stats-every 30s -oA scans/tcp-all TARGET
nmap -sT -n -sV -sC -p PORTS -oA scans/tcp-services TARGET
sudo nmap -sU -n --top-ports 20 -oA scans/udp-top20 TARGET

Read: initial TCP gives quick leads; -p- covers TCP 1-65535; -sV -sC acts only on the discovered PORTS; UDP is a separate 20-port sample. Start service enumeration while wider coverage runs.

Build one line per useful endpoint:

SOURCE -> TARGET | tcp/udp PORT | STATE | APPLICATION EVIDENCE | COVERAGE LIMIT | NEXT TEST

Carry that line into the service opportunity sheet and append access context, namespace/object, effective right, result and next action. New hosts/routes/listeners return here; a new credential normally triggers authenticated service re-enumeration instead of an automatic complete rescan.

Command chooser

Check source and route

ip -br addr
ip route get TARGET

Decisive output: the intended interface and source address. A route does not prove two-way reachability.

Discover an assigned host, list or subnet

nmap -sn -n -oA scans/host TARGET
nmap -sn -n -iL targets.txt -oA scans/hosts
nmap -sn -n -oA scans/subnet SUBNET

Choose SUBNET only when the whole CIDR is assigned. No response is not proof that a host is off.

Initial/common TCP selection

sudo nmap -sS -n -oA scans/tcp-initial TARGET

Coverage: Nmap's 1,000 common TCP ports, not ports 1-1000.

Full TCP coverage

sudo nmap -sS -n -p- --stats-every 30s -oA scans/tcp-all TARGET

Coverage: TCP 1-65535. This says nothing about UDP.

No raw-packet privileges

nmap -sT -n -p- --stats-every 30s -oA scans/tcp-all-connect TARGET

Choose connect scanning for ordinary OS connections. A SYN scan normally requires elevated raw-packet access.

Known-running target skipped by discovery

sudo nmap -sS -Pn -n --reason -p PORTS -oA scans/tcp-recheck TARGET

-Pn skips liveness proof; it does not fix a bad route. Read actual port responses, not only a host-up label.

Selected ports across an assigned list

sudo nmap -sS -n -p PORTS -iL targets.txt -oA scans/tcp-service-sweep

Useful for locating one service family. It is not a full port map.

TCP through an established SOCKS route

proxychains nmap -sT -Pn -n --top-ports 100 -oA scans/tcp-proxy-top100 TARGET

Only ordinary TCP connect calls traverse this route. SYN and UDP probes do not become proxy-compatible. Record the 100-port limit.

Identify applications on discovered TCP ports

nmap -sT -n -sV -p PORTS -oA scans/tcp-services TARGET
nmap -sT -n -sV -sC -p PORTS -oA scans/tcp-services-default TARGET

Use the first for application probes; add default scripts only when their interactions answer a useful question. A version match is an exploit candidate, not proof.

Inspect and run one named NSE script

nmap --script-help http-headers
nmap -sT -n -p PORTS --script http-headers -oA scans/http-headers TARGET

Decisive output: behavior or metadata relevant to the chosen question. Read script help before use. The example performs an HTTP HEAD request for /.

UDP common sample, focused detail and full coverage

sudo nmap -sU -n --top-ports 20 -oA scans/udp-top20 TARGET
sudo nmap -sU -n --top-ports 100 -oA scans/udp-top100 TARGET
sudo nmap -sU -n -sV -p PORTS -oA scans/udp-detail TARGET
sudo nmap -sU -n -p- --stats-every 60s -oA scans/udp-all TARGET

Choose a bounded sample first, a protocol-aware focused probe when a candidate matters, and full UDP only when the objective/time justifies it. Silence can remain open|filtered; full coverage can be slow.

Verify one TCP endpoint

nc -nv -w 3 -z TARGET PORTS
sudo nmap -sS -n -v --reason -p PORTS -oN scans/tcp-check.txt TARGET

Use one port for the Netcat check. Success confirms connection acceptance; refusal is explicit rejection; timeout is unresolved. --reason shows what drove Nmap's classification.

Windows source position

Test-NetConnection -ComputerName TARGET -Port PORTS
22,80,443,445,3389 | % {echo ((New-Object Net.Sockets.TcpClient).Connect("TARGET", $_)) "TCP port $_ is open"} 2>$null

Use one port with Test-NetConnection. The loop prints successful ordinary TCP connections and hides errors; no line does not classify a port as closed. Results belong to the Windows host's route and filtering context.

State decisions

StateWhat it establishesNext action
openAn endpoint accepted the selected connection/probe from this sourceIdentify and enumerate the application
closedExplicit rejection in this contextMove on unless target/source state later changes
filteredFiltering, loss or path behavior prevented a decisionDiagnose only when the endpoint matters
unfilteredReachable by the chosen probe; open versus closed unresolvedUse a scan type that answers that distinction
`openfiltered`Either listening silently or filtered
`closedfiltered`Either rejected or filtered

A port-number service label is a clue. -sV, protocol behavior and configuration evidence raise confidence. None of them alone proves exploitability.

Prioritization

Prefer the cheapest test likely to produce one of these:

  1. direct anonymous or supplied-credential access;
  2. exposed files, configuration, backups or useful metadata;
  3. a clear application/product/configuration prerequisite for a public exploit;
  4. credentials, names, shares or routes that expand another surface;
  5. a decisive disproof that lets you leave a path.

Investigate applications, not port stereotypes. Keep an explicit return item for incomplete full TCP, UDP or application coverage.

Rescan triggers

  • New route, source host or tunnel: repeat the relevant network checks from that position.
  • Target restart or changed assignment: confirm the IP and refresh affected results.
  • New credential or identity: re-enumerate authentication-dependent service behavior; a complete port rescan is not automatically necessary.
  • Foothold: inspect local and internally bound listeners, then map how to reach them.
  • Higher privilege: re-enumerate protected configuration, credentials, services and routes.
  • Lossy or inconsistent evidence: repeat only the decisive focused test with the same tuple and clearer diagnostics.

Do not repeat an unchanged disproven scan merely because an exploit failed.

Failure repair

SymptomCheck
Every host appears downPortal/target state, current IP, interface and route; then one assigned known endpoint
SYN scan lacks privilegesUse sudo or switch to -sT
Discovery omits a known-running targetFocused -Pn scan and actual response reasons
Only filtered resultsRoute/source, loss and one known/relevant endpoint
Kali and Windows disagreeHold target, transport, port and time constant before blaming source filtering
Scan is slowUDP silence, service probes, retries, loss and selected coverage; use progress output
Few resultsConfirm default/common versus selected/range/full port coverage
tcpwrapped or early closeTreat as an early-close observation, not a product or vulnerability; probe further only if identity matters

Evidence minimum

Save commands and output with different prefixes. Record source, target, transport, selected ports, discovery mode, scan type, time, state, application confidence, uncertainty and the next action. -oA PREFIX writes normal, grepable and XML output; keep the readable .nmap and the raw formats.

Sources: supplied PEN-200 2025 edition, sections 6.4.2-6.4.3, pp142-156; Nmap port states, scan techniques, version detection, NSE usage, timing, and output. Supplemental source: Hexdump live enumeration cheatsheet.

Discover and recognize candidates

Use these discovery checks to find a candidate, then validate the missing conditions. Cues are illustrative; complete synthetic outputs and three-outcome examples are in the linked study entries.

Discover attack surfaces

Find: Validate the source path and discover hosts

From the assessment host inspect the assigned interface and the route to the exact target before interpreting silence.

ip addr
ip route get TARGET
nmap -sn SUBNET -oA host-discovery

Recognize: The route names the intended interface/source; a responder is evidence from that source, not a global reachability claim.

Validate next: Check scope, target state and whether host-discovery probes are permitted by this path.

Validate the source path and discover hosts.

Find: Discover TCP ports with SYN or connect scans

After path validation, compare a first TCP pass with explicit full-port coverage; record skipped discovery or privilege limitations.

nmap -Pn -sT --top-ports 1000 TARGET -oA tcp-initial
nmap -Pn -sT -p- TARGET -oA tcp-full

Recognize: The high listener exists outside the first selection; its application label remains provisional.

Validate next: Confirm scan completion, source, errors and application behavior on each interesting port.

Discover TCP ports with SYN or connect scans.

Find: Identify applications and validate selected NSE checks

Take the discovered open-port list and request protocol/version evidence rather than choosing attacks from conventional port numbers.

nmap -Pn -sV -p PORTS TARGET -oA selected-services

Recognize: An HTTP response on a nonstandard port routes investigation to application mapping; a product string is still only fingerprint evidence.

Validate next: Verify normal requests, hostname/TLS requirements and exact build/configuration before selecting an exploit.

Identify applications and validate selected NSE checks.

Find: Probe UDP and resolve ambiguous silence

Inspect discovery results and DNS/SNMP/RPC clues, then probe a separate bounded UDP selection from the same source.

sudo nmap -Pn -sU --top-ports 20 --reason TARGET -oA udp-initial

Recognize: A DNS response confirms a UDP application; open|filtered SNMP silence is a candidate requiring a correctly formatted request.

Validate next: Check accepted service parameters, response identity and possible ICMP rate limiting.

Probe UDP and resolve ambiguous silence.

Find: Validate uncertain results and rebuild the service queue

Compare saved scan results with one direct connection and a service-native request for the endpoint that changes your next decision.

nc -nvz TARGET PORT
nmap -Pn -sT -p PORT --reason TARGET

Recognize: Independent TCP reachability supports an endpoint candidate, not credentials, read permission or execution.

Validate next: Identify the application and validate the particular next-layer action.

Validate uncertain results and rebuild the service queue.

Find: Enumerate reachable endpoints from a Windows source

From the Windows foothold inspect interfaces/routes, then check an assigned internal host's selected service ports.

Get-NetIPConfiguration
Get-NetRoute -AddressFamily IPv4
Test-NetConnection TARGET -Port 445

Recognize: The service is reachable from this Windows source; this can reveal a useful vantage point unavailable from Kali.

Validate next: Confirm application/authentication and whether a forward or a native client can use that route.

Enumerate reachable endpoints from a Windows source.

Find: Discriminate unknown listeners and use scanner alternatives

Select an unexplained listener from the saved queue, compare native connection behavior, then use focused version/TLS probes.

nmap -Pn -sV --version-all -p PORT TARGET
nc -nv TARGET PORT

Recognize: TLS and an HTTP redirect suggest a hostname-selected web application rather than an attack tied to the port number.

Validate next: Reproduce the hostname/TLS request and confirm exact software/configuration.

Discriminate unknown listeners and use scanner alternatives.
