    10.2.1 Decision loop

     
    CONFIRM APPLICATION
  -> TEST LEAST-PRIVILEGED CONTEXT (anonymous/null/known credential)
  -> LIST NAMESPACE BEFORE COPYING/QUERYING
  -> MEASURE READ / WRITE / ADMIN / EXECUTE RIGHTS SEPARATELY
  -> EXTRACT NAMES, FILES, CONFIGURATION, CREDENTIAL CLUES
  -> VALIDATE THE CHEAPEST DECISIVE HYPOTHESIS
  -> RE-ENUMERATE AFTER NEW IDENTITY, HOST, ROUTE OR ACCESS
    OutputSafe conclusionNext action
    Authentication acceptedIdentity/method works for this protocolEnumerate authorization; do not assume session/admin rights
    Read succeedsThis identity can read that objectInspect locally; map disclosed names/credentials
    Write succeedsThis identity can alter that object/pathFind consumer, execution identity and trigger before claiming execution
    Access deniedThis object/action denied in this contextTry a legitimately acquired identity or a different allowed object
    Timeout/silenceCause unresolvedCheck route, transport, version and a protocol-aware probe

    10.2.2 Find accessible files and usable access through FTP FTP

     
    ftp TARGET
# anonymous / email-like password; then: status, pwd, ls -la, binary, get FILE

nmap -sV -p PORT --script ftp-anon,ftp-syst TARGET
curl --list-only ftp://TARGET/
curl -o FILE ftp://TARGET/path/FILE
curl --user USER --upload-file ./probe.txt ftp://TARGET/path/probe.txt

    230 accepts login; 530 rejects that login. Upload proves write only. Full FTP procedure.

    10.2.3 Validate SSH identity and available access SSH

     
    ssh -v -p PORT USER@TARGET
chmod 600 KEY
ssh -v -i KEY -p PORT USER@TARGET
nmap -p PORT --script ssh-auth-methods --script-args "ssh.user=USER" TARGET

    Separate route, host-key, method, credential and shell-policy failures. Spraying/cracking is a later block. Full SSH procedure.

    10.2.5 Expand the host map through DNS records and zone transfers DNS

    10.2.6 Find accessible exports and validate their permission mappings NFS and Unix RPC

    10.2.6.1 rpcinfo -p TARGET

    rpcinfo -p TARGET
showmount -e TARGET
nmap -sV -p 111,2049 --script nfs-showmount,nfs-ls,nfs-statfs TARGET

sudo mkdir -p /mnt/nfs-audit
sudo mount -t nfs -o ro,vers=3,nolock TARGET:/EXPORT /mnt/nfs-audit
ls -lan /mnt/nfs-audit
find /mnt/nfs-audit -maxdepth 3 -ls
sudo umount /mnt/nfs-audit

    10.2.6.2 Only when a harmless write check is required:

    # Only when a harmless write check is required:
sudo mount -t nfs -o rw,vers=3,nolock TARGET:/EXPORT /mnt/nfs-audit
touch /mnt/nfs-audit/probe-file
ls -ln /mnt/nfs-audit/probe-file
rm /mnt/nfs-audit/probe-file
sudo umount /mnt/nfs-audit

    NFSv4-only servers may not answer showmount. Interpret numeric UID/GID, root_squash, write rights and privileged consumption separately. Full Unix file-services procedure.

    10.2.6.3 Rsync daemon — list modules, then retrieve selected artifacts 
    nmap -sV -p 873 --script rsync-list-modules TARGET
rsync rsync://TARGET/
rsync --list-only rsync://TARGET/MODULE/
rsync -av rsync://TARGET/MODULE/path/FILE ./FILE

    A module listing proves namespace visibility, not read/write/execute. Retrieve only selected material; never use remote --delete during enumeration. Interpretation and variants.

    10.2.6.4 TFTP — retrieve an evidence-backed filename 
    tftp TARGET
tftp> binary
tftp> get FILE
tftp> quit

    TFTP has no directory listing or login step. A timeout does not distinguish a missing name, blocked UDP or transfer-policy failure. Upload only when the objective requires a write check and a cleanup route exists. Interpretation and write boundary.

    10.2.7 Find shares, identities and rights through SMB and RPC SMB and MS-RPC

    Run/context: SMB/RPC clients run on the testing workstation against the named server, using an explicit anonymous, local or domain identity. Decide: share listing does not establish file read, write or execution. Validate the exact object with the complete SMB procedure; send a recovered secret to credential classification, and record a denied object as denied in this context.

    smbclient -N -L //TARGET
smbclient -L //TARGET -U 'DOMAIN/USER'
smbclient //TARGET/SHARE -U 'DOMAIN/USER'
smbclient -L //TARGET -U 'TARGET/USER'
smbclient -L //TARGET -U 'guest%'
# pwd, ls, allinfo FILE, get FILE

rpcclient -U '' -N TARGET
rpcclient -U 'DOMAIN/USER' TARGET
# srvinfo, enumdomains, enumdomusers, enumdomgroups, queryuser RID, netshareenumall

nxc smb TARGET -u USER -p PASSWORD --shares
enum4linux-ng -A TARGET
nmap -p 139,445 --script smb-protocols,smb2-security-mode,smb2-time TARGET

    net view \\TARGET /all
Get-ChildItem \\TARGET\SHARE
Get-Content \\TARGET\SHARE\FILE

    Null, guest and authenticated sessions can expose different namespaces. Confirm useful results manually. Full SMB/RPC procedure.

    Need: A confirmed reachable application; anonymous context or one identified credential. Anonymous login allowed or a valid FTP identity; data-channel connectivity and object-specific read/write rights

    Recognize: FTP usually appears on TCP/21, but trust an FTP banner or protocol response on any port. Goal: determine authentication, listable/readable content and effective write locations.

    At the prompts, try user anonymous and an email-like password. Then:

pwd
ls -la
binary
get FILE
quit

    Next action: inspect recovered files; record exact read/write boundaries; validate any new credential once against its likely service; send a writable-consumer hypothesis to the appropriate web, execution or privilege-escalation block.

    Failure cues: timeout suggests route/filtering/service issues; refusal means no accepting listener in that context; host-key failure occurs before user authentication; Permission denied proves that the attempted method/context failed, not that every credential is invalid. A valid account may still have no shell or be restricted by server policy.

    Next action: after a shell, verify whoami, groups, hostname and addresses, then re-enumerate locally. Password spraying and key-passphrase cracking belong to the credential-attack block, not this procedure.

    nmap -sV -p 111,2049 --script nfs-showmount,nfs-ls,nfs-statfs TARGET

    Decisive output: a named module and a file listing establish only that the current anonymous or supplied account can enumerate that namespace. Read access is proven by retrieving selected bytes, not by the module name.

    Prerequisite: LDAP reachability. Coverage: RootDSE only; this can work even when directory searches require authentication. Decisive output: defaultNamingContext and dnsHostName.

    ldapsearch -x -LLL -H ldap://TARGET:389 -s base -b '' \
  defaultNamingContext rootDomainNamingContext configurationNamingContext dnsHostName

    Convert DC=corp,DC=example into corp.example for DNS/Kerberos work. Preserve the server's exact hostname because Kerberos is name-sensitive.

    10.2.14.1.33.1.1 LDAPS and certificate-name inspection 
    openssl s_client -connect TARGET:636 -servername DC_HOST </dev/null
ldapsearch -x -LLL -H ldaps://DC_HOST:636 -s base -b '' defaultNamingContext dnsHostName

    A certificate can disclose domain/DC names. A TLS validation error is a client trust/name issue, not proof that LDAP is unavailable.

    10.2.14.1.33.2 Check which directory objects are readable without credentials Anonymous directory search

    Prerequisite: known base DN and server permitting anonymous search. Failure cue: Inappropriate authentication or Insufficient access closes only the anonymous path.

    ldapsearch -x -LLL -H ldap://DC_IP:389 -b 'DC=DOMAIN,DC=TLD' \
  '(&(objectCategory=person)(objectClass=user))' \
  sAMAccountName userPrincipalName memberOf description

    ldapsearch -x -LLL -H ldap://DC_IP:389 -b 'DC=DOMAIN,DC=TLD' \
  '(objectClass=group)' cn member description
    10.2.14.1.33.3 Query directory objects with your accepted identity Authenticated search

    Prerequisite: a valid directory identity. Decisive output: objects/attributes unavailable anonymously. Avoid placing a real password in shell history when an interactive prompt is available.

    ldapsearch -x -LLL -H ldap://DC_HOST:389 \
  -D 'USER@DOMAIN.TLD' -W -b 'DC=DOMAIN,DC=TLD' \
  '(&(objectCategory=person)(objectClass=user))' \
  sAMAccountName userPrincipalName memberOf description servicePrincipalName userAccountControl
    10.2.14.1.33.3.1 Search computers, groups and SPN-bearing accounts separately 
    ldapsearch -x -LLL -H ldap://DC_HOST:389 -D 'USER@DOMAIN.TLD' -W \
  -b 'DC=DOMAIN,DC=TLD' '(objectClass=computer)' \
  dNSHostName operatingSystem operatingSystemVersion servicePrincipalName

ldapsearch -x -LLL -H ldap://DC_HOST:389 -D 'USER@DOMAIN.TLD' -W \
  -b 'DC=DOMAIN,DC=TLD' '(objectClass=group)' cn member

ldapsearch -x -LLL -H ldap://DC_HOST:389 -D 'USER@DOMAIN.TLD' -W \
  -b 'DC=DOMAIN,DC=TLD' '(&(objectCategory=person)(servicePrincipalName=*))' \
  sAMAccountName servicePrincipalName memberOf
    10.2.14.1.33.4 Kerberos prerequisites before an attack

    Kerberos failures are often name/time/route failures rather than credential failures. Establish:

    getent hosts DC_HOST
nc -nvz DC_IP 88
date -u
nmap -Pn -sV -p 88,389,445,464,636,3268,3269 DC_IP -oN dc-services.txt

    Interpretation: resolve DOMAIN and DC_HOST consistently, keep clock skew within Kerberos tolerance, and ensure the KDC is reached through the selected route. KDC_ERR_C_PRINCIPAL_UNKNOWN points to identity/domain naming; KRB_AP_ERR_SKEW points to time; KDC_ERR_PREAUTH_FAILED normally points to authentication material.

    10.2.14.1.33.5 Continue with the capability your result enables Handoff
    • New users, groups, computers, SPNs or domain names → domain mapping.
    • A user confirmed without preauthentication → Kerberos and identity transitions.
    • Valid credentials → rerun authenticated LDAP plus SMB/share/remote-access enumeration.
    • Certificate templates/AD CS clues → AD CS and object-control abuse.

    Verify: Record DC, base DN, bind identity and actual returned attributes; RootDSE alone is not a complete directory dump.

    If it fails: Stronger-auth-required may mean TLS/signing policy; invalid credentials or an empty base require different fixes.

    10.2.14.2.1 Inspect a Java RMI registry before selecting an exploit

    • Enter: service detection or an application response identifies Java RMI on a selected port.

    • Discover: enumerate bound names, classes, remote endpoints and codebase annotations without assuming the registry is exploitable:

      nmap -sV -p PORT --script rmi-dumpregistry TARGET

    • Validate: confirm the selected endpoint is the actual registry/service, its class-loading/serialization behavior, Java/version prerequisites and whether any proposed test is intrusive. The Nmap class-loader probe is categorized intrusive and must not be the baseline:

      nmap -p PORT --script rmi-vuln-classloader TARGET

    • Execute: no generic RMI/serialization execution procedure is registered. Route a matched component/version/condition to exploit prerequisite matching only after the required behavior is established; see the pending action procedure.

    • Verify: registry names or a vulnerable class-loader result are component evidence, not a session. A complete action must separately verify the executed identity and resulting capability.

    • Outcomes: matching component and vulnerable behavior → candidate for reviewed exploit prerequisite matching procedure; no registry or prerequisite decisively absent → ruled out here; filtered/incomplete registry or ambiguous class loading → inconclusive.

    • Sources: Nmap rmi-dumpregistry and rmi-vuln-classloader.

    10.2.14.2.3 Follow an MSSQL linked server as a new SQL identity boundary

    • Enter: a working MSSQL login reveals one linked server or login mapping.
    • Discover: enumerate sys.servers and sp_helplinkedsrvlogin, preserving local login, remote server, provider/data source and mapping.
    • Validate: test one read-only remote identity query through the supported RPC or data-access mechanism. Do not enable RPC, create mappings or change configuration for enumeration.
    • Execute: MSSQL linked-server and login-context mapping.
    • Verify: record returned SYSTEM_USER, ORIGINAL_LOGIN() and the remote role result. A remote SQL query is not OS command execution.
    • Outcomes: mapped remote query succeeds → re-enter database identity for that server/identity; link exists but RPC/data access is decisively unavailable → ruled out for that mechanism; mapping/authentication/provider failure is unresolved → inconclusive/failed-boundary diagnosis.
    10.2.14.2.4 Documented commands and conditions

    Treat a linked server as another authentication and authorization boundary. The local SQL login, its mapped remote login, remote SQL role and RPC/data-access settings can all differ.

    SELECT SYSTEM_USER AS current_login,
       ORIGINAL_LOGIN() AS original_login,
       SUSER_SNAME() AS effective_login,
       IS_SRVROLEMEMBER('sysadmin') AS is_sysadmin;

SELECT name, product, provider, data_source, is_linked
FROM sys.servers
WHERE is_linked = 1;

EXEC master.dbo.sp_helplinkedsrvlogin;

    Interpret: sys.servers proves configuration, not remote access. sp_helplinkedsrvlogin shows local-to-remote mappings; a NULL local login can represent a mapping that applies to all local logins. Preserve the local and remote identities separately.

    After selecting one named link, test the smallest remote query supported by its configuration:

    EXEC ('SELECT SYSTEM_USER AS remote_login,
              ORIGINAL_LOGIN() AS remote_original_login,
              IS_SRVROLEMEMBER(''sysadmin'') AS remote_is_sysadmin')
AT [LINKED_SERVER];

    If RPC execution is disabled but data access is allowed, use a read-only pass-through query instead:

    SELECT *
FROM OPENQUERY([LINKED_SERVER],
  'SELECT SYSTEM_USER AS remote_login,
          ORIGINAL_LOGIN() AS remote_original_login');

    Decide: a returned remote identity enables only the operations granted to that mapped login. RPC OUT is disabled, login-mapping failures and data-access failures rule out different mechanisms; they do not prove the server is unreachable. If enum_impersonate identifies a specific permitted login, test only that login and always return to the original context:

    EXECUTE AS LOGIN = 'LOGIN';
SELECT SYSTEM_USER, ORIGINAL_LOGIN(), SUSER_SNAME(), IS_SRVROLEMEMBER('sysadmin');
REVERT;

    Do not enable RPC, create mappings or change server configuration merely to enumerate. A remote SQL query is not OS execution; independently validate any file or command facility and the operating-system identity behind it.

    Sources: Microsoft sys.servers, sp_helplinkedsrvlogin, EXECUTE AS, and OPENQUERY.
