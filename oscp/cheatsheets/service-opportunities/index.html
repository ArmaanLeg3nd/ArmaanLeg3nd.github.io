Service Opportunity Cheatsheet

← Cheatsheet index · Previous: discovery and scanning · Complete procedures · Mechanics | Strategy map | Study methods: Extract opportunities from services

Use this after application identification. Commands are examples for explicitly authorized targets; replace every placeholder.

Enter with the discovery tuple and extend it:

SOURCE -> TARGET | TRANSPORT/PORT | APPLICATION EVIDENCE | COVERAGE LIMIT
       | ACCESS CONTEXT | NAMESPACE/OBJECT | ACTION | RESULT | NEXT

Decision loop

CONFIRM APPLICATION
  -> TEST LEAST-PRIVILEGED CONTEXT (anonymous/null/known credential)
  -> LIST NAMESPACE BEFORE COPYING/QUERYING
  -> MEASURE READ / WRITE / ADMIN / EXECUTE RIGHTS SEPARATELY
  -> EXTRACT NAMES, FILES, CONFIGURATION, CREDENTIAL CLUES
  -> VALIDATE THE CHEAPEST DECISIVE HYPOTHESIS
  -> RE-ENUMERATE AFTER NEW IDENTITY, HOST, ROUTE OR ACCESS
OutputSafe conclusionNext action
Authentication acceptedIdentity/method works for this protocolEnumerate authorization; do not assume session/admin rights
Read succeedsThis identity can read that objectInspect locally; map disclosed names/credentials
Write succeedsThis identity can alter that object/pathFind consumer, execution identity and trigger before claiming execution
Access deniedThis object/action denied in this contextTry a legitimately acquired identity or a different allowed object
Timeout/silenceCause unresolvedCheck route, transport, version and a protocol-aware probe

FTP

ftp TARGET
# anonymous / email-like password; then: status, pwd, ls -la, binary, get FILE

nmap -sV -p PORT --script ftp-anon,ftp-syst TARGET
curl --list-only ftp://TARGET/
curl -o FILE ftp://TARGET/path/FILE
curl --user USER --upload-file ./probe.txt ftp://TARGET/path/probe.txt

230 accepts login; 530 rejects that login. Upload proves write only. Full FTP procedure.

SSH

ssh -v -p PORT USER@TARGET
chmod 600 KEY
ssh -v -i KEY -p PORT USER@TARGET
nmap -p PORT --script ssh-auth-methods --script-args "ssh.user=USER" TARGET

Separate route, host-key, method, credential and shell-policy failures. Spraying/cracking is a later block. Full SSH procedure.

SMTP

nc -nv TARGET PORT
# EHLO example.invalid
# HELP
# VRFY USER
# EXPN postmaster
# QUIT

openssl s_client -connect TARGET:587 -starttls smtp -crlf -quiet
openssl s_client -connect TARGET:465 -crlf -quiet
smtp-user-enum -M VRFY -U users.txt -t TARGET -p PORT

252 is inconclusive, not a confirmed user. Compare response codes and final multiline reply. Full SMTP procedure.

DNS

dig @TARGET DOMAIN SOA
dig @TARGET DOMAIN NS
dig @TARGET DOMAIN MX
dig @TARGET DOMAIN TXT
dig @TARGET -x IP
dig @TARGET DOMAIN AXFR
dnsrecon -d DOMAIN -n TARGET -t std
dnsrecon -d DOMAIN -n TARGET -D WORDLIST -t brt
dnsenum --dnsserver TARGET DOMAIN
dnsrecon -r SUBNET -n TARGET

nslookup HOST.DOMAIN TARGET
nslookup -type=TXT HOST.DOMAIN TARGET

AXFR refusal disproves only that transfer attempt. NXDOMAIN differs from NOERROR with no answer. Check wildcard results. Full DNS procedure.

NFS and Unix RPC

rpcinfo -p TARGET
showmount -e TARGET
nmap -sV -p 111,2049 --script nfs-showmount,nfs-ls,nfs-statfs TARGET

sudo mkdir -p /mnt/nfs-audit
sudo mount -t nfs -o ro,vers=3,nolock TARGET:/EXPORT /mnt/nfs-audit
ls -lan /mnt/nfs-audit
find /mnt/nfs-audit -maxdepth 3 -ls
sudo umount /mnt/nfs-audit

# Only when a harmless write check is required:
sudo mount -t nfs -o rw,vers=3,nolock TARGET:/EXPORT /mnt/nfs-audit
touch /mnt/nfs-audit/probe-file
ls -ln /mnt/nfs-audit/probe-file
rm /mnt/nfs-audit/probe-file
sudo umount /mnt/nfs-audit

NFSv4-only servers may not answer showmount. Interpret numeric UID/GID, root_squash, write rights and privileged consumption separately. Full NFS/RPC procedure.

SMB and MS-RPC

smbclient -N -L //TARGET
smbclient -L //TARGET -U 'DOMAIN/USER'
smbclient //TARGET/SHARE -U 'DOMAIN/USER'
smbclient -L //TARGET -U 'TARGET/USER'
smbclient -L //TARGET -U 'guest%'
# pwd, ls, allinfo FILE, get FILE

rpcclient -U '' -N TARGET
rpcclient -U 'DOMAIN/USER' TARGET
# srvinfo, enumdomains, enumdomusers, enumdomgroups, queryuser RID, netshareenumall

nxc smb TARGET -u USER -p PASSWORD --shares
enum4linux-ng -A TARGET
nmap -p 139,445 --script smb-protocols,smb2-security-mode,smb2-time TARGET

net view \\TARGET /all
Get-ChildItem \\TARGET\SHARE
Get-Content \\TARGET\SHARE\FILE

Null, guest and authenticated sessions can expose different namespaces. Confirm useful results manually. Full SMB/RPC procedure.

SNMP

onesixtyone -c COMMUNITY_FILE TARGET
snmpwalk -v2c -c COMMUNITY TARGET 1.3.6.1.2.1
snmpbulkwalk -v2c -c COMMUNITY TARGET 1.3.6.1.2.1

# users, processes, installed software, TCP listeners
snmpwalk -v1 -c COMMUNITY TARGET 1.3.6.1.4.1.77.1.2.25
snmpwalk -v1 -c COMMUNITY TARGET 1.3.6.1.2.1.25.4.2.1.2
snmpwalk -v1 -c COMMUNITY TARGET 1.3.6.1.2.1.25.6.3.1.2
snmpwalk -v1 -c COMMUNITY TARGET 1.3.6.1.2.1.6.13.1.3
snmpwalk -v3 -l authPriv -u USER -a SHA -A AUTH_PASSWORD -x AES -X PRIV_PASSWORD TARGET 1.3.6.1.2.1

No response can be community, version, OID, loss or filtering. A write community is not permission to alter state during enumeration. Full SNMP procedure.

LDAP and Kerberos

ldapsearch -x -LLL -H ldap://DC_IP:389 -s base -b '' defaultNamingContext dnsHostName
ldapsearch -x -LLL -H ldap://DC_HOST:389 -D 'USER@DOMAIN' -W \
  -b 'DC=DOMAIN,DC=TLD' '(&(objectCategory=person)(objectClass=user))' \
  sAMAccountName userPrincipalName memberOf description servicePrincipalName

getent hosts DC_HOST
nc -nvz DC_IP 88
date -u

RootDSE may work when anonymous directory search does not. Kerberos failures often come from DNS/hostname/SPN/time/route rather than the password. Full LDAP/Kerberos procedure.

Databases

MySQL / MariaDB

mysql -h TARGET -P PORT -u USER -p

SELECT VERSION(), USER(), CURRENT_USER();
SHOW DATABASES;
SHOW GRANTS;
USE DATABASE;
SHOW TABLES;
SELECT * FROM TABLE LIMIT 20;
SELECT @@secure_file_priv;

MSSQL

impacket-mssqlclient 'USER@TARGET'
impacket-mssqlclient 'DOMAIN/USER@TARGET' -windows-auth

SELECT @@VERSION;
SELECT SYSTEM_USER;
SELECT IS_SRVROLEMEMBER('sysadmin');
SELECT name FROM sys.databases;

PostgreSQL

psql -h TARGET -p PORT -U USER -d postgres
# \conninfo  \l  \du  \dn  \dt *.*

SELECT version(), current_user, session_user;
SELECT pg_has_role(current_user, 'pg_execute_server_program', 'member');

DB admin is not OS admin. Server file/program functions act as the DB service identity and require explicit grants. Full database procedure.

Windows remote access

xfreerdp3 /v:TARGET /u:USER /d:DOMAIN /auth-only /cert:ignore
xfreerdp3 /v:TARGET /u:USER /d:DOMAIN /dynamic-resolution /cert:ignore
nmap -p 3389 --script rdp-enum-encryption,rdp-ntlm-info TARGET

evil-winrm -i TARGET -u USER
evil-winrm -i TARGET -u 'DOMAIN\\USER'
evil-winrm -i TARGET -u USER -S -P 5986

$cred = Get-Credential
Enter-PSSession -ComputerName TARGET -Credential $cred

Valid credentials may still lack RDP logon or WinRM endpoint rights. Check the installed FreeRDP/Evil-WinRM help for version-specific spelling. Full Windows remote-access procedure.

SMBMap and authenticated SMB/RPC collection

Use an accepted account and reachable SMB; inspect one share before downloading a selected file.

smbmap -H TARGET -d DOMAIN -u USER -p 'PASSWORD' --no-write-check
smbmap -H TARGET -d DOMAIN -u USER -p 'PASSWORD' -r 'SHARE' --depth 2 --no-write-check
smbmap -H TARGET -d DOMAIN -u USER -p 'PASSWORD' --download 'SHARE\PATH\FILE' --no-write-check
enum4linux-ng -A -w DOMAIN -u USER -p 'PASSWORD' TARGET

A readable config/backup → classify the value and test the matching service. Share-list denial does not rule out a known share path. Full SMB/RPC procedure.

Discover and recognize candidates

Use these discovery checks to find a candidate, then validate the missing conditions. Cues are illustrative; complete synthetic outputs and three-outcome examples are in the linked study entries.

Extract opportunities from services

Find: Use anonymous or authenticated FTP file access

After identifying FTP, test the allowed anonymous context or one known credential and inspect its directory namespace.

curl -v ftp://TARGET/
curl -v --user 'USER:PASSWORD' ftp://TARGET/

Recognize: A listing identifies candidate artifacts; a completed RETR with recognizable bytes establishes read access.

Validate next: Validate the account context, file contents, data-channel reachability and any separate write/consumer conditions.

Use anonymous or authenticated FTP file access.

Find: Use SSH passwords, keys and forwarding-capable access

Find SSH in service discovery, then trace a candidate password/key back to its recorded user before a bounded authentication attempt.

ssh -v -p PORT USER@TARGET
ssh -v -i KEY -p PORT USER@TARGET

Recognize: Accepted key authentication plus a verified shell identity establishes that specific login, not root or unrestricted forwarding.

Validate next: Check actual account/shell/subsystem and separately inspect forwarding policy if a tunnel is needed.

Use SSH passwords, keys and forwarding-capable access.

Find: Enumerate SMTP identities and accessible mailbox protocols

Identify mail-related listeners, inspect greeting/capabilities and compare permitted user-discovery replies with a known-invalid control.

nc -nv TARGET 25

Then enter the protocol dialogue:

EHLO example.invalid
VRFY USER
VRFY INVALID_CONTROL
QUIT

Recognize: A reproducible reply difference can expose a possible mailbox identity.

Validate next: Check catch-all policy and account context; recipient acceptance does not prove mailbox credentials or OS access.

Enumerate SMTP identities and accessible mailbox protocols.

Find: Expand names through DNS records and zone transfers

Use DNS-server evidence and discovered domain names to query authority and specific records before considering a transfer.

dig @TARGET DOMAIN SOA
dig @TARGET DOMAIN NS
dig @TARGET DOMAIN AXFR

Recognize: An authoritative zone and returned records can expose hostnames, aliases and applications needing separate enumeration.

Validate next: Check each new name's scope/address and verify host/virtual-host behavior.

Expand names through DNS records and zone transfers.

Find: Inspect RPC/NFS exports and effective file identity

Follow RPC/NFS discovery with export inspection, then examine actual ownership/mapping on an allowed mount.

rpcinfo -p TARGET
showmount -e TARGET

Recognize: An export lists a filesystem candidate and client policy; it does not establish file access or trusted UID 0.

Validate next: Use the owning procedure to verify NFS version, allowed client, numeric identity mapping, read/write and squash/mount policy.

Inspect RPC/NFS exports and effective file identity.

Find: Enumerate SMB/RPC shares, files and identities

Start from confirmed SMB and explicitly compare anonymous versus a known authenticated context, then open a relevant named share.

smbclient -L //TARGET -N
smbclient -L //TARGET -U 'DOMAIN/USER'

Recognize: A share name supplies a filesystem investigation target; listing it does not prove read, write or service creation.

Validate next: Connect to the named share under the identity that listed it, then ls/get the exact object. Listing a share does not prove read or write. For a write candidate, verify the path operation and identify a separate execution consumer before treating it as access.

Enumerate SMB/RPC shares, files and identities.

Find: Extract configuration and process information through SNMP

Take UDP/161 evidence and a justified management credential/community, then request a small known OID branch before a broad walk.

snmpwalk -v2c -c COMMUNITY TARGET 1.3.6.1.2.1.1

Recognize: A real OID response confirms the accepted read context and supplies software/name clues.

Validate next: Determine which useful views/branches are actually readable; process data and write rights are separate.

Extract configuration and process information through SNMP.

Find: Use MySQL/MariaDB data and file primitives

Use a known application/database login and inspect identity, grants and file-operation constraints before choosing an OS transition.

SELECT USER(),CURRENT_USER(),VERSION();
SHOW GRANTS;
SHOW VARIABLES LIKE 'secure_file_priv';

Recognize: SELECT permits data investigation; absent FILE/admin rights and the restricted directory constrain file/OS hypotheses.

Validate next: Check exact grants, useful tables, destination OS permissions and an execution consumer before escalating a file operation.

Use MySQL/MariaDB data and file primitives.

Find: Use SQL Server rights, impersonation and command facilities

Once SQL Server authentication works, inspect actual login/server role and supported impersonation context.

SELECT SYSTEM_USER, ORIGINAL_LOGIN(), @@VERSION;
SELECT IS_SRVROLEMEMBER('sysadmin');

Recognize: A valid login with sysadmin=0 is data/rights evidence, not permission to enable xp_cmdshell.

Validate next: Enumerate actual database/server grants and useful impersonation; independently verify any OS facility and its identity.

Use SQL Server rights, impersonation and command facilities.

Find: Use PostgreSQL data and privileged program execution

Authenticate to the observed database and inspect current/session identity and role attributes before program/file functions.

SELECT current_user,session_user,version();
SELECT rolname,rolsuper FROM pg_roles WHERE rolname=current_user;

Recognize: An ordinary database role does not automatically have COPY PROGRAM or server-file access.

Validate next: Inspect effective role memberships and exact operation rights, then the database service's OS context.

Use PostgreSQL data and privileged program execution.

Find: Inspect Redis access and persistence boundaries

Identify Redis and use its authentication context to distinguish accepted commands from denied administrative facilities.

redis-cli -h TARGET -p PORT PING

Recognize: The connection is usable but command ACLs can remove persistence/configuration methods.

Validate next: Inspect allowed operations, data visibility and actual persistence/destination/consumer conditions.

Inspect Redis access and persistence boundaries.

Find: Triage Oracle listener and database identity

Use service discovery and an application's connection descriptor to distinguish listener identification from a valid database session.

nmap -Pn -sV -p 1521 TARGET

Recognize: Listener/product evidence and a service name establish a connection candidate, not database credentials or DBA rights.

Validate next: Validate the exact descriptor/account and inspect its permitted database action.

Triage Oracle listener and database identity.

Find: Validate RDP, WinRM, VNC and Telnet access contexts

Take remote-access listeners from discovery and validate one known identity against the specific endpoint/logon type.

Test-NetConnection TARGET -Port 3389
Test-NetConnection TARGET -Port 5985

Recognize: Transport offers an RDP candidate from this source; it does not establish remote-interactive rights.

Validate next: Check actual protocol, local/domain context, accepted authentication and endpoint/logon authorization.

Validate RDP, WinRM, VNC and Telnet access contexts.

Find: Discover LDAP naming contexts and authenticated search

Identify the directory endpoint and query RootDSE before a subtree search under a known bind identity.

ldapsearch -x -LLL -H ldap://DC_IP -s base -b '' defaultNamingContext namingContexts

Recognize: RootDSE supplies the search base; it does not grant arbitrary anonymous subtree access.

Validate next: Check bind identity, transport/signing requirements and read visibility on the selected objects.

Discover LDAP naming contexts and authenticated search.

Find: Investigate SIP/IRC identity and configuration clues

Classify the unusual listener, then use its normal greeting/registration behavior and the owning procedure's bounded protocol checks.

nmap -Pn -sV -p PORT TARGET
nc -nv TARGET PORT

Recognize: The real protocol and registration state determine the next client operation; the expected port label is insufficient.

Validate next: Verify application/version, accepted interaction and exact exploit/access conditions.

Investigate SIP/IRC identity and configuration clues.
