    10.12.0.1 Define LDAPSearch once in this PowerShell session

    Requires Windows PowerShell/.NET directory access, domain DNS and an authenticated directory context. No RSAT or PDC-specific connection is required. Paste the complete definition once; subsequent calls reuse it.

    function LDAPSearch {
    [CmdletBinding()]
    param(
        [Parameter(Mandatory=$true)][ValidateNotNullOrEmpty()][string]$LDAPQuery,
        [string]$Server,
        [string]$SearchBase,
        [string[]]$Properties = @('samaccountname','distinguishedname','memberof','serviceprincipalname','description')
    )
    $root = $entry = $searcher = $results = $null
    try {
        $prefix = if ($Server) { "LDAP://$Server/" } else { 'LDAP://' }
        if (-not $SearchBase) {
            $root = New-Object System.DirectoryServices.DirectoryEntry($prefix + 'RootDSE')
            $SearchBase = [string]$root.Properties['defaultNamingContext'][0]
            if (-not $SearchBase) { throw 'No default naming context; specify Server and SearchBase.' }
        }
        $entry = New-Object System.DirectoryServices.DirectoryEntry($prefix + $SearchBase)
        $searcher = New-Object System.DirectoryServices.DirectorySearcher($entry)

}

    10.12.18.4.33 Inspect VSS/shadow-copy credential-source conditions

    • Enter: you control a Windows Server/DC context where offline credential material is relevant and the token may hold administrative or backup rights.
    • Discover: inspect whoami /priv, vssadmin list shadows, then diskshadow → list shadows all.
    • Validate: establish platform, exact volume, existing-versus-new snapshot, read rights, matched NTDS.dit and SYSTEM-hive requirement, output destination and cleanup authority.
    • Execute: shadow-copy boundary checks. Creating/exposing/deleting a shadow and acquiring the matched files remain unavailable until the pending action procedure is complete.
    • Verify: listing proves only snapshot metadata. Credential acquisition requires readable, point-in-time-compatible NTDS/SYSTEM material and successful offline parsing.
    • Outcomes: suitable existing snapshot and read path identified → ready for the pending action procedure procedure; platform/rights/volume/source decisively incompatible → ruled out here; snapshot listed but access/freshness/matching hive unresolved → inconclusive.
    • Source: Microsoft DiskShadow.

    Boundary: discovery/validation only; the action procedure is pending.

    10.12.18.4.35 Evaluate a direct Net-NTLMv2 relay path without spoofing

    10.12.18.4.36 Inspect AD-integrated DNS record control

    • Enter: AD-integrated DNS is present and a selected zone or record object may be writable by the current principal.

    10.12.18.4.37 Separate an unconstrained-delegation flag from tickets actually present

    • Enter: a computer/service account has TrustedForDelegation/unconstrained delegation and the selected host/session context is accessible.
    • Discover: confirm the account/SPNs and inspect the actual selected ticket cache with klist or Rubeus.exe triage in the permitted context.
    • Validate: ticket owner, realm, service/TGT type, validity, logon-session/LUID access, export/cache compatibility and the exact receiving service. A delegation flag without a cached client ticket is only configuration.
    • Execute: when a relevant ticket already exists, use the ticket classification and cache procedure and movement preflight. Forced/coerced authentication remains unavailable under the pending action procedure.
    • Verify: prove one named service action under the ticket principal, then preserve the host/LUID/cache scope. Do not record a password, hash or domain-wide privilege.
    • Outcomes: usable cached ticket accepted by the named service → ticket and key context/remote operation preflight; no relevant ticket in the inspectable context → current cached-ticket path ruled out; inaccessible LUID, stale ticket or ambiguous principal → inconclusive.
