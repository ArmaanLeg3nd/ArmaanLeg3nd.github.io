linWinPwn: collect, then triage

One launch command. Four collection choices. Follow the useful leads manually.

Use it like an AD first-pass collector: map identities, relationships, permissions and shares, then investigate the strongest finding. It reduces command juggling; it does not prove that a suggested attack path works.

OSCP boundary: use the selected enumeration actions below. Do not use --auto or “run all” batches: the reviewed automatic path includes attack routines and vulnerability probes. Automated enumeration is permitted; automatic exploitation, mass vulnerability scanning and spoofing are restricted. This is feature-based guidance, not blanket OffSec approval of linWinPwn. Official rules · Exam FAQ.

1. Start with your domain account

Run from Kali with linWinPwn installed, working AD DNS/time and routed access to the DC. Replace DC_IP, DOMAIN, USER, PASSWORD and TARGET. Use a private output directory.

mkdir -p ~/oscp/work/TARGET/evidence/linwinpwn
linWinPwn -t DC_IP -d DOMAIN -u 'USER' -p 'PASSWORD' --targets DC -o ~/oscp/work/TARGET/evidence/linwinpwn

Scope: --targets DC limits host routines that honor it; it does not constrain every collector. BloodHound “all methods” contacts domain hosts independently. Use it only when those hosts are in scope; otherwise choose DCOnly. Startup itself contacts the DC and scans selected ports.

Have a hash or ticket instead? Choose one alternative

NTLM hash: use the matching account and LM:NT material.

linWinPwn -t DC_IP -d DOMAIN -u 'USER' -H 'LM_HASH:NT_HASH' --targets DC -o ~/oscp/work/TARGET/evidence/linwinpwn

Kerberos cache: use a valid cache for the intended identity; DNS, service names and clock alignment must be correct.

linWinPwn -t DC_IP -d DOMAIN -u 'USER' -K /absolute/path/USER.ccache --targets DC -o ~/oscp/work/TARGET/evidence/linwinpwn

Use one credential method per run. Child-tool credential support differs. Keep secrets, tickets and output private.

Only when the first pass leaves a specific gap
  • 2 → 9 — delegation inventory with findDelegation/NetExec when you need a readable delegation check.

Do not select the attack, vulnerability-check, dumping, object-modification or command-execution menus from this sheet. An individual technique needs its own reviewed procedure; its exclusion here does not imply that OffSec forbids every technique in those menus.

3. Turn the output into your next check

Results live under ~/oscp/work/TARGET/evidence/linwinpwn/linWinPwn_DOMAIN/. Read individual collector files and errors, not just completion banners. Keep different runs/identities separate so old output does not become new evidence.

FindingNext action
BloodHound CE JSON in DomainRecon/Import into a compatible Community Edition instance. Inspect a candidate path and verify each useful permission before acting.
Interesting identity, group or writable object in DomainRecon/Check the exact identity, effective rights, object type and inheritance. A writable-object label is a candidate, not confirmed escalation.
Readable share in Shares/Read a specific relevant file. Share visibility alone does not establish useful contents, local admin or execution.
Denied, missing or empty resultsCheck the collector's credentials, dependency and connectivity. Failed collection does not prove that the attack surface is absent.

Re-enumerate after obtaining a new identity or access level. Save the identity, command and decisive output for each useful lead.

4. If collection fails

  • Login failure: stop retries; confirm account/domain, credential and account state. Stop if the wrapper unexpectedly prompts to change a password.
  • LDAP or Kerberos failure: check DC reachability, DNS, clock and signing/channel-binding requirements. Use the focused AD procedure for transport-specific commands.
  • [X] Missing: repair the named dependency; the wrapper is not a self-contained bundle.
  • Graph import failure: match the CE collector output to a compatible BloodHound CE importer.

Do not fix an uncertain result by switching to --auto. Use the specific collector directly if its wrapper behavior is unclear.

Sources & one-time setup

Tooling for this section: linWinPwn coordinates BloodHound CE, ldapdomaindump, bloodyAD and NetExec. A domain account plus the relevant LDAP/SMB/Kerberos connectivity is the baseline; host/session collection needs additional reachability and rights. Use direct collectors and setup when you need one focused check.

For linWinPwn installation, follow the upstream setup instructions. Review the installer first: it installs/upgrades many dependencies, uses sudo and writes under /opt/lwp-scripts. No installation or target execution is established by this sheet.
