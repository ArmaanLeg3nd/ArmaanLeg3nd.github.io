Database Enumeration and Privilege Boundaries

← Stage index · Cheatsheet | Strategy map | Study methods: Extract opportunities from services

Recognize: common ports include MSSQL 1433, MySQL/MariaDB 3306 and PostgreSQL 5432, but instances can use other ports. Goal: establish database identity, authentication context, databases/schemas/tables, granted rights, useful data, server-side file access and command execution only where explicit privileges permit it.

Database administrator and operating-system administrator are different identities. Server-side file/program features act in the database server's filesystem and service-account context, not Kali's.

MySQL / MariaDB

mysql -h TARGET -P PORT -u USER -p

SELECT VERSION(), USER(), CURRENT_USER();
SHOW DATABASES;
SHOW GRANTS;
USE DATABASE;
SHOW TABLES;
DESCRIBE TABLE;
SELECT * FROM TABLE LIMIT 20;
SELECT @@secure_file_priv;

Interpret: USER() shows the presented client identity; CURRENT_USER() shows the account used for privilege checking. secure_file_priv restricts server-side import/export: a directory constrains it, an empty value is unrestricted by that variable, and NULL disables these operations. The FILE privilege is still required.

MySQL variant — validate server-side file read/write prerequisites 
SELECT LOAD_FILE('/path/on/database/server');
SELECT 'probe' INTO OUTFILE '/allowed/server/path/probe.txt';

Use only an authorized harmless path. LOAD_FILE returning NULL is ambiguous among missing file, permissions, size, FILE privilege and secure_file_priv. INTO OUTFILE will not overwrite an existing file. A written file becomes execution only if another privileged component consumes it.

Microsoft SQL Server

impacket-mssqlclient 'USER@TARGET'
impacket-mssqlclient 'DOMAIN/USER@TARGET' -windows-auth

Let the tool prompt for the password. At the SQL prompt:

SELECT @@VERSION;
SELECT SYSTEM_USER;
SELECT IS_SRVROLEMEMBER('sysadmin');
SELECT name FROM sys.databases;
USE DATABASE;
SELECT TABLE_SCHEMA, TABLE_NAME FROM INFORMATION_SCHEMA.TABLES;
SELECT TOP 20 * FROM SCHEMA.TABLE;

Interpret: IS_SRVROLEMEMBER('sysadmin') returns 1, 0 or NULL; NULL is not success. Impacket also exposes helpers such as enum_impersonate and xp_cmdshell depending on version and rights.

MSSQL variant — command-execution boundary 
EXEC xp_cmdshell 'whoami';

xp_cmdshell is disabled by default on new installations. Enabling it generally requires high privilege and changes server configuration; do not enable it merely to enumerate. When available, a sysadmin's child process normally runs as the SQL Server service account; an authorized non-sysadmin may use a configured proxy. Verify returned identity before choosing the next action.

PostgreSQL

psql -h TARGET -p PORT -U USER -d postgres

\conninfo
\l
\du
\dn
\dt *.*

SELECT version(), current_user, session_user;
SELECT rolname, rolsuper, rolcreaterole, rolcreatedb
FROM pg_roles;
PostgreSQL variant — server file/program privilege boundary 
SELECT pg_has_role(current_user, 'pg_read_server_files', 'member');
SELECT pg_has_role(current_user, 'pg_write_server_files', 'member');
SELECT pg_has_role(current_user, 'pg_execute_server_program', 'member');

Server-side COPY ... FROM/TO 'file' uses the PostgreSQL server's filesystem and service identity. COPY ... PROGRAM executes on the server and requires superuser or the corresponding predefined role. Client-side \copy reads/writes the client filesystem and is not the same primitive.

Failure cues: connection refusal/timeout is network or listener context; login rejection is authentication/context; an empty database list may be visibility limits; object denial is authorization. Query only bounded rows first. Never assume that reading application credentials or obtaining database admin implies OS execution.

Next action: identify application accounts, hashes/credentials, paths and linked systems; record the precise grant enabling any file or execution primitive; validate recovered credentials in the later credential block and re-enumerate after any identity change.

Redis

nmap -Pn -sV --script redis-info -p PORT TARGET
redis-cli -h TARGET -p PORT PING
redis-cli -h TARGET -p PORT INFO
redis-cli -h TARGET -p PORT ACL WHOAMI
redis-cli -h TARGET -p PORT ACL LIST

Authenticated when a password is legitimately known:

redis-cli -h TARGET -p PORT --askpass

PONG proves an accessible Redis command surface, not write/file/execution permission. Check ACLs, mode, bind/protected-mode and persistence/module configuration before reasoning about an effect. Do not run CONFIG SET, write keys or load modules during enumeration.

Oracle TNS/SID triage

nmap -Pn -sV --script oracle-tns-version -p 1521 TARGET
nmap -Pn --script oracle-sid-brute -p 1521 TARGET

A discovered SID/service name is a namespace clue, not credentials. Continue with an installed Oracle client only when a legitimate identity is available; preserve listener/version/SID evidence and do not treat a conventional port as Oracle proof. Source supplement: reviewed getSH Nmap Oracle block.

MongoDB — inspect readable databases with mongosh

Use when the service is MongoDB, commonly TCP/27017. Current installations use mongosh; the old mongo binary may be absent.

# Reachable service without known credentials
mongosh --host TARGET --port PORT

# Known account; -p prompts rather than storing the password in the command
mongosh --host TARGET --port PORT -u USER -p --authenticationDatabase admin

Inside mongosh, choose the real database/collection:

show dbs
use DATABASE
show collections
db.getCollection('COLLECTION').find().limit(5)
db.getCollection('users').findOne({username: 'USER'})

Read: returned documents prove that identity can read those collections. An empty database list can reflect authorization, not an empty server. Classify recovered secrets and use the matching service. Login/operator injection is an application query issue, distinct from direct DB access. Do not overwrite account records just because the repo contains an update example.

SQLite — inspect a recovered application database

Use when a downloaded/local application file is SQLite. It is a file format, not a remote listener.

file app.db
sqlite3 -readonly app.db

.tables
.schema users
PRAGMA table_info(users);
SELECT * FROM users LIMIT 5;
.quit

Read: identify the schema and credential format before choosing a recovery mode. Keep the database's provenance and any required WAL/SHM companions; a locked/incomplete copy can give misleading results. Recovered passwords/hashes → the credential procedure, not an assumption of OS or domain access.
